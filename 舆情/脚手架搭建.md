# 舆情与事件模块 · 脚手架与实施说明

供 **双层日报子页面**、Yuqing Worker、D1 与 Cron 对齐；**未接通能力一律保留 PLANNED 占位**，勿随意删除。

---

## 〇、两条子页面与推荐开发工作流（先 mock，后接真模型）

舆情与事件在主导航下拆为两个路由，各司其职：

| 路由 | 名称 | 页面脚本 | Worker 报表 kind |
|------|------|----------|------------------|
| `#/news` | 事件一览 | `js/pages/events.js` | `daily_event` |
| `#/news-analysis` | 舆情分析 | `js/pages/news.js` | `sentiment_analysis` |

**逻辑关系（闭环）**：事件一览侧重 **事实池 + 「信息底座」结构化展示**，不主推交易结论；舆情分析读取 **最近一次 `daily_event` 日报**（`grounding.basedOnDailyReportId`），叠加 **行情/衍生品快照** 与按需增量采集，产出 **二次研判** JSON。Cron 时点设计为：**先事件日报，再舆情分析**（详见 `wrangler.yuqing.toml` 注释与 `settings` 舆情定时说明）。

### 推荐开发顺序（与你的协作方式对齐）

1. **改本地 mock，定稿展示契约**  
   - 分别在 `events.js` 内的日报 mock、`news.js` 内的舆情 mock 上调版式与字段展示。  
   - mock 的 **`report` 对象结构与字段命名**必须与 Worker 落库、`GET /api/yuqing/reports/*` 返回体一致；仅改文案风险小，**新增板块或改嵌套**时须同步 Worker 拼装逻辑，否则接云后会缺格或错位。

2. **同步改 LLM / 搜索相关提示与编排（以 Worker 为唯一真相源）**  
   - 长篇、联网与 JSON 仪表盘类 prompt 在 **`cloudflare/yuqing-worker.js`**（如 flash、今日头条/动态速览、AI 情报、趋势等）。  
   - `舆情/日报/ribao-cloudflare/` 可作草稿参考；**定稿必须合并进上述 Worker**，避免「本地 HTML 满意、线上仍是旧 prompt」分叉。  
   - 旧单页各 LLM 模块的**输出形态、字段粒度与 mock 对齐说明**（从 `index.html` 拆解）：见 **`舆情/日报/旧日报-LLM模块与Mock参照.md`**。

3. **接入密钥与模型，跑真实闭环**  
   - 配置 `GEMINI_API_KEY` / `GOOGLE_API_KEY`、`YUQING_LLM_PROVIDER=gemini`，并按需设置 `YUQING_LLM_MODEL_FLASH` / `YUQING_LLM_MODEL_PRO` / `YUQING_LLM_MODEL_FAST_PROSE` / `YUQING_LLM_MODEL_TRENDS` 等。  
   - 真数据除 LLM 外还依赖 **D1 事实池、ingest、Finnhub/行情 API**；若与 mock 文案有差距，优先查 **事实条目是否带 URL、市场快照是否完整、LLM 降级与 `sourceErrors`**，而非只调前端 mock。

### 事件一览定稿口径（2026-05-05）

- 顶部不展示「赛博前哨站」类大标题，改为早报/午报/晚报分段、报告日期、生成时间、事件覆盖信息与报告库/扫描按钮。
- 页面可用于定稿预览，但前端可见文案不得出现 `Mock`、脚手架解释、开发说明、`本页只展示事实底座格式` 等字样。
- 「高价值事件拆解」至少呈现 3 条，结构保持：事实锁定、结构拆解、传导预判。
- 「动态速览」展示结构为：事件、描述、简单分析；LLM 搜索范围限定最近 72 小时，但前端不显示 `48-72h` 标签。
- 「趋势线索」观察窗口统一为 `0-72小时`，覆盖最新事实到后续跟踪信号。
- 保留「AI 情报站」结构；底部不再展示单独的「来源可信度」窗口。
- 每次改前端 mock 呈现时，同步调整 `cloudflare/yuqing-worker.js` 内 daily_event 的 LLM/搜索 prompt 与结构化拼装，保证接入 API key 后真实日报形态贴近定稿页。

## 一、信息架构（事实池 + 双层结构化日报 + 按需 LLM）

- **服务端事实池**：聚合源经 Cron / 手工 ingest 写入 **D1** `yuqing_items`、`yuqing_snapshots`（保留时长以 Worker `prune*` 逻辑为准）。
- **双子页主线（现行）**：`#/news`、`#/news-analysis` **仅**通过 **`fetchYuqingReportLatest` / `fetchYuqingReportItem` / `fetchYuqingReportHistory`** 拉 **`yuqing_reports`**，**不**把 `GET /api/yuqing/latest` 当首屏数据源（该方法仍在 `js/data-engine.js` 保留，给其他场景或排障使用）。
- **双层日报**：`daily_event` 与 `sentiment_analysis` 写入 **`yuqing_reports`**；单条载荷含 `report`、`grounding`、`sourceRefs`、`sourceErrors` 等。
- **按需 / 兼容路径**：仍可 **`POST /api/yuqing/report`**（兼容舆情编排）；生成落库以 **`POST /api/yuqing/reports/generate`**（body 带 `kind`）等为常用入口。
- **按需解读与搜索**：`buildReport` 内以事实 **grounding** 为主；事实偏少、`allowSearch` / `forceSearch`、或 **`YUQING_LLM_ALWAYS_SEARCH=1`** 等条件下启用 **Google 搜索补洞**（配额与稳定性需自控）。

## 二、后端 · `yuqing` Worker

| 项 | 说明 |
|----|------|
| 代码 | `cloudflare/yuqing-worker.js`；事实与 D1 辅助：`cloudflare/yuqing-facts.js` |
| 配置 | `cloudflare/wrangler.yuqing.toml`（独立于 btc Worker）；配置 D1 **`database_id`** |
| Cron | `wrangler.yuqing.toml` 内 `[triggers] crons`：覆盖 **北京时间** 事件日报 **00/08/12/20** 与舆情分析 **09/14/22**（UTC 表达式见文件内注释） |
| 手工 ingest | `POST /api/yuqing/ingest`，请求头 **`X-Yuqing-Cron-Secret`** 与 **`CRON_SECRET`** 一致 |

### 主要 HTTP 路由（摘要）

- `GET /api/yuqing/health` — 健康、D1、`secrets` 摘要、模型名提示
- `GET /api/yuqing/sources`、`GET /api/yuqing/latest`、`GET /api/yuqing/items`、`GET /api/yuqing/history` — **事实池 / 条目列表 / 快照类**接口（≠ 报表双子页默认入口）
- **`GET /api/yuqing/reports/latest?kind=daily_event|sentiment_analysis`**
- **`GET /api/yuqing/reports/history?kind=…&days=7`**
- **`GET /api/yuqing/reports/item?id=…`**
- **`POST /api/yuqing/reports/generate`** — 按 kind 生成并写入 D1
- `POST /api/yuqing/report` — 兼容旧路径（舆情编排）
- `POST /api/yuqing/llm/test` — LLM 连通性

### D1 迁移

- `cloudflare/migrations/yuqing/0001_init.sql` — `yuqing_snapshots`、`yuqing_items`、`yuqing_report_runs` 等
- `cloudflare/migrations/yuqing/0002_reports.sql` — **`yuqing_reports`** 等日报表结构
- 远程执行以 toml 中库名为准：`npx wrangler d1 execute <DB_NAME> --remote --file=...`

### 典型 Secrets / 环境变量

- **`FINNHUB_API_KEY`**
- **`CRON_SECRET`**
- **Gemini**：`GEMINI_API_KEY` / `GOOGLE_API_KEY`，`YUQING_LLM_PROVIDER`，及各 **`YUQING_LLM_MODEL_*`**
- **`YUQING_LLM_ALWAYS_SEARCH=1`** — 慎用（配额）

## 三、前端 · 双子页面

| 路由 | 页面 | 说明 |

| 样式 | `styles.css` 中 `news-*`、`yuqing-*` 等 |
