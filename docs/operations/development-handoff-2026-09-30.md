## 精确下一步

1. 新电脑先完成启动验收，核对七周期切换、四页导航和时间；只在出现真实错误时继续修改读取链路。不要恢复旧整窗秒轮询，或扩大超时掩盖慢 SQL。
2. 产品主线转向使用事件/舆情流程完成一次真实研究；按需导入、读回并在页面复核。页面里的旧报告仍是历史，不代表本次正式研究已经完成。
3. 数据治理以实际缺口为入口。最近仍出现宏观陈旧值、3 日线未核实/缺口标识和足迹形成中部分组成；逐项核对当前读回，再决定能否从原始来源回补。没有证据不得直接改成“已核实”，提速不等于全部数据最新。
4. 强平和逐笔流的停采历史未必可恢复；保持分所、覆盖和限制。新增供应商、付费订阅、保留量或采集频率是新的方案取舍，不由换电脑自动引入。
5. 交易执行、员工、会议室和复盘中的规划/演示是独立后续方向，尚未授权实现时保留。接续本主线无需再进行一次全仓重构。

## Git 与私密迁移

- Git 包含本次源码、样式、测试、说明、云端配置标识和开关记录；不包含真实凭据、依赖缓存、构建产物或本机数据库。
- 桌面私密 ZIP 保存当前 `.env`、出口机本地记录、SSH 密钥对和旧私密包；另附恢复说明与 ZIP SHA-256。按路径合并并修正旧电脑绝对路径。
- ZIP 未加密，仅供离线拷贝。GitHub、Cloudflare、Codex 在新电脑重新登录，不迁移 Cookie 或 OAuth 缓存。
- 私密包不是完整云端备份：不含无法导出的 Cloudflare Secrets，也不含 D1/DO 内容。现有服务继续使用原账号资源。
