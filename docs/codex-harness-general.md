# Codex Harness 通用增强说明

Codex 的 harness 目标不是让模型“变聪明”，而是让模型更稳定地拿上下文、用工具、执行、验证和复盘。

## 推荐文件形态

- `AGENTS.md`：仓库级 Codex 工作约定，放启动方式、验证命令、禁忌和汇报格式。
- `.codex/skills/<skill-name>/SKILL.md` 或项目 `skills/<skill-name>/SKILL.md`：可触发的专业工作流。
- `docs/*.md`：较长说明、架构图、验证矩阵、故障排查手册。
- `package.json` / `Makefile` / `justfile`：把验证闭环变成稳定命令。
- `scripts/*`：把重复性检查写成确定性脚本，少靠口头记忆。

## Harness 能力清单

- 上下文：明确入口、模块边界、架构图、数据流、常见坑。
- 工具：提供本地启动、lint、test、API smoke、截图检查、diff 摘要命令。
- 权限：默认读写项目；联网、安装依赖、部署、生产数据访问需要审批。
- 记忆：把个人偏好写入 `AGENTS.md` 或 skill，例如中文总结、少重构、先看测试。
- 验证：改完自动选择最小验证集，失败后先定位并修复，再报告残余风险。
- 复盘：最终回复包含改动文件、验证结果、未跑检查和下一步建议。

## 推荐闭环

1. 读上下文：`AGENTS.md`、项目规则、相关入口、现有测试。
2. 制定最小改动面：确认模块边界和不能碰的占位结构。
3. 实施：小步 patch，保留用户已有改动。
4. 验证：按改动类型运行 lint/test/API/browser 检查。
5. 修复：失败先看日志、定位、补测试或修实现。
6. 总结：运行 diff 摘要，说明改了什么、验证了什么、还剩什么风险。

## 可补充的高级能力

- 只读数据库 MCP：让 Codex 查 schema、样本数据和线上只读状态。
- GitHub/GitLab MCP：自动读 PR、issue、CI 和 review comments。
- 日志系统 MCP：把错误堆栈和请求链路接进排障流程。
- 浏览器自动化：前端改动自动截图、交互 smoke、canvas 非空检查。
- 发布护栏：部署命令单独审批，生产密钥和交易 API 禁止默认访问。
