# 开发期间的云端异常读取检测

日期：2026-10-05。范围：BTC 项目三个 D1 数据库。风险 L2：新增本地检测和开发启动检查，复用官方 Analytics，无远程业务写入。BTC继续暂停。随后进行的[根因本地修复](d1-cost-repair-implementation-2026-10-06.md)已单独记录，不能用检测结果替代实际D1计费验收。

## 使用与强制汇报

- `npm run cloud:reads`：查询现有 Cloudflare Analytics/Query Insights，检查本地历史初始化 SQL，生成 `.artifacts/cloud-read-monitor/latest.md` 与 `latest.json`，保留最近 24 份 JSON。使用本机官方 Wrangler 登录，凭据只在内存内传递，不输出原始 SQL、参数或认证返回值。
- `npm run dev:local`（包括调用它的 BAT）：端口监听成功后检查一次，此后每次检查完成 5 分钟再查，开发终端显示所有问题。关闭开发服务时等待本次有界检查完成，不留下新的定时任务。进程清理无法确认时停止后续检查并报警。
- 开发任务开始、结束必须检查并在当前对话汇报 `ALERT`、`REVIEW`、`UNKNOWN`；规则已写入仓库 `AGENTS.md`。无需等待用户专门询问费用。检测失败本身也是需要报告的问题。
- `npm run cloud:reads -- --offline`：只检查源码，明确云端未核验。`npm run verify:cloud-reads` 是离线回归，已经接入 `verify:all`；它验证检测器能识别问题，不表示真实用量正常。
- 检测脚本退出码：0 当前覆盖范围未命中；2 有异常；3 需要核查或无法判断。开发告警不会关闭编辑器、修改业务数据或自动恢复云端。`verify:all` 的离线回归门槛验证检测器本身；真实用量结论必须看单独执行的 `cloud:reads`，不能用 build PASS 覆盖它的异常状态。

## 检测口径

数据库范围从 `cloudflare/cloud-control-state.json` 的三个项目 Worker 绑定推导，去重共享的 BTC_DB，并校验项目账号、Worker 和数据库数。没有遍历账号其他系统。每轮仅一次 GraphQL Analytics 请求，不发 D1 SQL 或生产业务 API。

| 规则 | 判定与反馈 |
| --- | --- |
| 已知重复扫描 | 生成三个实际历史初始化入口的 SQL，发现事故中的 `NOT EXISTS + AND EXISTS` 形态立即 ALERT；这是源码风险，不是实时费用证明 |
| 项目总读取量 | 最新完整观察窗口 15 分钟超过 100 万行，或过去 24 小时超过 1 亿行，ALERT；三个库合计，避免分散负载漏报 |
| 突增 | 前后相邻 15 分钟比较，前一窗口至少 10 万行且增加至至少 5 倍，ALERT |
| 初始化无产出 | 同一初始化 SQL 至少 20 次、10 万读取、平均每次至少 1000 行，写入 0 行，ALERT |
| 扫描放大 | 同样的调用/规模下限，读取/返回至少 100 倍，REVIEW；正常聚合和写语句也可能命中，不能直接称作浪费 |
| 暂停后活动 | 本地已记录暂停后，留出 5 分钟并向上取整到完整分钟；最近 60 分钟观察中仍有读写或查询则 ALERT。手工诊断也可能造成读取，需查来源 |
| 检测盲区 | 登录失效、网络/API 异常、指标缺字段、负数、重复、越界、账号不匹配、分钟活动有记录而日汇总缺失为 UNKNOWN；无近期活动记录、近期有查询但 SQL 统计缺失、SQL Top N 截断为 REVIEW |

阈值位于 `scripts/diagnostics/cloud-read-policy.json`。它们是本次选用的工程告警线，不是 Cloudflare 配额、用户批准的支出预算或自动断费开关。SQL 每库只取近 15 分钟读取量最高的 20 种；读取总量独立汇总，不靠 Top N 相加估算。

时间统一存 UTC，窗口右端不含。当前时间向下取整到分钟并减 5 分钟作为结束；这只是本地给指标延迟留的余量，不是官方数据完整性保证。过去 24 小时总量可能包含停机前高费用，报告明确区分。查询不存在记录时保留 `null`，不能把“没看到数据”报告成实时 0 行。暂停时间来自本地恢复记录，不替代 `cloud:status` 的实时配置核对。

## 执行边界

- 每次检查由仓库既有 `run-bounded` 监督，业务进程硬截止 40 秒，进程清理最多另 15 秒；Wrangler 认证调用最多 12 秒，Analytics 网络请求最多 15 秒。监督器记录本次 PID 和清理结论；开发关闭等待本次检查，不单杀父进程。
- 手动与开发服务可以同时检查，每个进程保存独立报告；开发服务按本次子进程 PID 和开始时间读回，避免把另一个检查的 `latest.json` 当作本次结果。`latest` 是便于阅读的副本；保存失败必须汇报。
- Wrangler 4.85.0 的 `auth token --json` 也会写调试日志。仅在本检测的认证子进程内，预加载一个针对专用日志路径的写入抑制器，保留官方登录与凭据缓存正常行为；不更改依赖包或全局设置。模拟测试和真实执行均确认该日志未落盘；早期两次验证产生的两份日志已按精确路径删除，未读取内容。
- 只有开发服务运行或助手主动执行命令时检查。它不是全天候服务，不能在助手未运行时主动发聊天消息；开发终端告警与 `AGENTS.md` 约束分别负责运行提示和对话汇报。
- 不覆盖 Workers/DO/存储及账号共用订阅费用，不检查 VPS，不承诺检测所有未定义的异常或实时硬停损。保留其他系统和共用订阅的既定决定。
- 未改业务 SQL、采集频率、模型运行、Cloudflare 配置、远程 D1 数据或生产页面；暂停优先，不部署本项改动。
