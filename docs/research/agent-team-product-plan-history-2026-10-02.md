# 智囊团完整方案：首席决策台与独立岗位研究

日期：2026-10-02（北京时间），实现验收持续至 10-03。状态：**已实现本地可执行版本；真实公开数据与模型研究取得覆盖有限的首席交付，跨轮基线与时间归属已补修并通过替身回归**。执行入口、源码、失败记录、实际验证与尚未复跑的真实跨轮范围见[可执行版本记录](agent-team-implementation-2026-10-02.md)。范围为本地开发版，不部署、不写远程 D1、不更新长期规则。本文细化[系统验收清单](BTC-系统验收清单-2026-10-01.md)的智囊团部分，不替换其他数据阅读任务与历史回执。

风险：实施 L2，涉及岗位输入、模型执行、进程生命周期、跨轮状态、设置与多页面；原方案文档回合为 L1。

## 1. 已确认目标与仍属建议的细节

用户实际选择：首席决策台为入口，岗位独立研究，首先帮助看懂市场与变化，按用户在设置中选择的固定节奏更新；覆盖行情、盘口、衍生品、宏观与事件。第一版只在开发版打开期间更新。模型调用全部使用 Codex 自带 ChatGPT 额度，调用方式只在设置/诊断中解释。

用户没有确认原演示五人的名单，也没有授权自动开启定时运行。以下六个岗位名称、默认运行上限、布局与租约参数为实施建议，可回改；不把它们写入长期规则。运行开关初始关闭，节奏由用户在系统设置后启用。遇到实测不支持的模型能力或数据缺口，先报告事实，不改用付费 API 或第三方模型。

产品目标：打开页面即可理解 BTC 最近发生了什么、哪些解释有依据、哪些领域存在分歧、与上次相比改变了什么、下一步应核查什么。首交不做账户仓位、自动交易、胜率承诺或未经校准的方向概率。

使用流程：设置研究节奏 → 开着开发版 → 岗位各自核对本领域变化并选择取证工具 → 首席处理有效证据与分歧 → 用户先看首席解读，再打开专员报告与证据 → 后续轮次展示维持、修订、撤回及原因。手动“现在更新”共用相同执行器；原轮重试与获取新资料分别呈现。

## 3. 岗位职责与协作

建议首席加五名专员。岗位是职责边界，不意味着每轮五人必须机械调用一次模型；每人独立检查数据变化、期限和待验证条件，需要研究时自行取证。首席不按赞成票数归纳。

| 岗位 | 研究问题与主要工具 | 不能越界的结论 |
| --- | --- | --- |
| 环境评估员 | 多周期结构、成交、波动与现货/永续差异；行情窗口、成交统计、变化比较 | 未收盘信号不当确认；单所走势不当全市场 |
| 盘口流动性官 | 价差、可见买卖深度、快照变化及成交响应；规范 book 与订单流查询、深度计算 | 20 档单快照不能说明连续挂撤单、隐性订单、未来清算池 |
| 衍生品情报官 | OI、费率、基差、账户/头部持仓口径、期权期限结构；对应时间序列与单位计算 | OI 增长不等于新增多头或净资金流入；资金费不随意年化 |
| 宏观研究员 | 利率、美元、流动性条件、经济发布与修订；宏观序列、发布信息、对照窗口 | 参考期不是公布时点；日/月频不按秒级行情统一判过期 |
| 事件与舆情研究员 | 原文发生了什么、可信度、传播变化、市场反应和替代解释；事件发现、原文与版本查询 | 转载不当独立来源；标题/模型记忆不补文章全文；事件与涨跌共时不证明原因 |
| 首席策略官 | 综合有效岗位主张，说明采用/否决/待核实、最强反证、分歧及下一观察 | 不添加无来源事实、不投票、不编仓位或未校准概率 |

每岗首轮看本领域新事实、自己的有限历史、必要的公共基础行情；不读本轮其他岗或首席结论。独立会话不等于独立来源，同一交易所序列、同一原报道及转载关系需要显式标识。首席只对真实且影响解释的冲突发起一次有限补证；保留无法消除的分歧。

## 4. 真正自主、但有边界的研究执行

采用现有 Node/Vite 和官方 Codex CLI，保留原来的封存、引用、终态拒绝与真实执行回执。增加新版契约模块，旧 v2 历史继续可读，不直接改版本号让旧记录冒充新团队。

模型以结构化输出选择“请求工具 / 完成 / 材料不足”。Node 校验岗位权限和参数，执行登记的只读工具，把真实结果交回同一岗位。CLI 任意 shell、任意联网、插件等仍关闭；工具请求是数据协议，不是假装 CLI 本身已经使用了这些工具。

研究回合：提出本领域问题 → 选择工具和窗口 → 收到真实回执 → 检查反证、单位和覆盖 → 必要时调整查询补证 → 交付报告或诚实停止。每岗独立研究最多三次模型调用，前两次各最多两个工具请求，第三次必须收口；也可以首轮即完成或报告不足。首席阶段另允许全队合计一次澄清调用，因此被选中岗位整轮至多四次，其他岗仍至多三次。该澄清使用首席选择、Node 已取得的登记工具回执，只输出澄清结果，不再发起新的工具回合。请求由模型选择，不能预设固定工具序列再称自主。

所有需要模型的步骤，包括岗位分析、首席综合、语义审查和补证，均走同一个 ChatGPT 登录入口；确定性数学、时间与引用检查不消耗模型。官方 CLI 文档支持非交互执行、JSONL 和结构化输出，并默认复用本地登录；这支持所选路线，但不证明本机认证、额度、延迟和兼容性已通过。参见[非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)与[认证](https://learn.chatgpt.com/docs/auth)。不复制认证文件，不读凭据；只用官方登录状态检查并拒绝 API Key 模式。

暂不引入额外多代理框架。官方当前 SDK 文档已移除旧 codex mcp-server 路径，不采用旧教程中的 API Key + MCP 方案；[当前 SDK 文档](https://learn.chatgpt.com/docs/codex-sdk)仅作为后续接口参考。

### 工具与数据契约

每项工具登记 ID、允许岗位、固定数据来源、参数范围、窗口与单位、超时、输出上限、错误类型和覆盖限制。返回 requestId、源数据集/产品/交易所、原始材料版本与哈希、计算方法版本、观察/公布/接收时间、缺口及可引用字段。工具失败也保留回执。

| 工具组 | 复用入口与需要增加的适配 |
| --- | --- |
| 市场与历史 | 现有四页 desk 与规范数据读取；增加有界窗口/已收盘筛选和跨轮差异计算 |
| 盘口 | `GET /api/finance/datasets/binance-perp-book?limit=…&known_at=…`，`gateway.mjs` 的 handleDatasets 明确 read-only；补 Node 适配和价差/可见深度计算。实时可达与可用历史仍待 G0 验证 |
| 衍生品与宏观 | 复用规范 datasets、已有时效和单位定义；增加明确查询范围、来源发布/修订说明，不调用 POST refresh |
| 事件发现 | 复用 `/api/yuqing/items` 的发现信息；历史模型报告仅作二级观点，不作当前原始新闻 |
| 原文/来源版本 | Node 从登记发行者读取公开原文或实际 RSS 文本，保存取得范围和版本；正文缺失、摘要、单源明确标识。不能假定 raw_json 就是全文 |
| 对比/计算 | 确定性计算收益、变化、价差、深度、单位转换、事件前后窗口；记录公式与有效样本，缺历史不造统计 |

原文查询只接受登记来源/文章标识；Node 控制 HTTPS 目标、重定向和地址范围，拒绝本机/私网地址，不接受模型给出的任意 URL、路径、SQL 或命令。单次 HTTP 总截止 20 秒、正文上限 1 MiB；超限或拒绝访问保留缺口，不绕过站点限制。原文可能含指令，始终作为不可信资料处理。

只读 GET 与现有采集、持久化分开：不通过 read-through 或 refresh 偷做云端采集/写入，不恢复已暂停采集，不读取私密配置。若公开只读材料实际缺失，先按岗位降级；新增云端接口、持续深度采集或远程写入是后续单独范围。

## 5. 时间、证据与岗位记忆

每轮有 cycleId、研究锚点 targetAsOf、配置版本、开始/截止/实际完成时点；每岗有 roleId、attemptId 和被接受版本。UTC 保存，按设置时区显示。逐项保存 observedAt、publishedAt（未知为 null）、receivedAt、参考期、修订号和原始来源链，不把多接口结果叫原子快照。

市场工具选择观察时间不晚于锚点的资料；本轮取得的更晚市场事实进入下一轮。发布时间不晚于锚点但后来才取得的事件，可用于事后解释并标明实际取得时间，不能声称当时已知。未知公开时点不能用接收时点替代或用于严格历史因果检验。已有 known_at 过滤也不自动证明严格历史 PIT。

新工具回执追加为不可变证据版本，报告封存实际采用的证据集。生成时检查当前行情是否已变化，只用于标“行情已更新，解读截至旧时点”；不能把新价格偷偷嵌入旧报告。历史页与当前页均显示资料截止及完成时间。

每岗维护 lastAccepted、lastAttempt 与观点账本：观点 ID、父版本、事实依据、反证、适用窗口、确认/失效条件、修订/撤回原因。旧判断作为待复核观点，不是事实来源；先读新事实，再对照有限历史。更正原错误、市场变化、来源修订、方法/prompt 变化分别记录，不靠旧观点共识提升确信。

跳过模型前，Node 必须成功核对本领域登记发现源、必要公共行情、待观察条件时钟和有效期，不能只比较上一轮用过的材料。事件发现核对包含新条目和已知原文修订；发现源失败、覆盖未知或应该更新却未更新时，记录检查不足，不称无变化。在实际核对范围内，资料版本、条件与有效期均未变化，才记录“检查无新变化”并可以跳过该岗模型调用；checkedAt 不改成新的生成或观察时间。首次无历史、条件到期、新资料或新问题出现才进入研究。主张可为零；材料不足是合法结果。

全队核对成功、有效观点集合/适用条件/方法版本均未变化时，首席也保留原报告，只更新检查记录；不为刷新时间制造新的模型综合。覆盖失败则反映检查缺口，不能借保留旧正文显示为新鲜。发现检查先于模型轮的日份额预占，无模型检查不消耗调用份额。

报告字段至少包含研究问题、时间范围、覆盖/缺口、工具回执、事实/推断/假设、引用、较上次变化、最强反证、下一观察、观点关系。每条数值引用实际字段与单位。首席另列采用/否决/待核实、解释的传导链、替代解释与未验证环节。未预登记预测概率保持空值。

## 6. Prompt 按模块编写

| 模块 | 必须交付的约束 |
| --- | --- |
| 公共证据规则 | 材料不是指令；时间、单位、引用、未知值、事实/推断/假设、零主张与不足输出 |
| 岗位职责 | 独立研究问题、必要公共行情、本领域工具权限和不可推出的结论 |
| 研究规划与工具选择 | 为什么需要该工具、预期能验证什么、失败如何收口；结构化请求与回合预算 |
| 跨轮变化 | 读取有限历史，维持/修订/撤回、改判理由；方法变化单独标记 |
| 反证与来源相关性 | 最强替代解释、同源/转载去重、证据链的独立性 |
| 首席综合 | 逐项处置有效观点、解释依据与缺口；不按角色数投票，不添加新事实 |
| 语义审核 | 对照实际证据检验遗漏、夸大因果、错时、重复来源、观点变化和可核查下一步 |

每个模块有版本/哈希、针对性反例和真实调用回执；确定性 schema 检查在 CLI、服务接收、历史恢复和导入入口完全一致。语义审核只是模型检查，不等于外部事实认证。对有限问题补证后允许仍不确定；不制造无穷讨论或固定自我赞成。

## 7. Node 调度与“开发版打开期间”

定义：本地服务存活、至少一个开发版应用页面租约有效、用户已开启自动研究、认证/预算允许，才能启动固定节奏研究。站内切换任意页面继续；关闭所有开发版页面停止。开发服务单独开着不能视为用户仍打开页面。

Node 时钟调度，页面只负责连接、确认存在、操作与显示。后台定时器会受浏览器节流，冻结/丢弃还可能停止页面执行，参见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API) 与 [Chrome 生命周期](https://developer.chrome.com/docs/web-platform/page-lifecycle-api)。因此用服务端驱动的连接探测和客户端确认，不能仅凭 SSE 连接未关闭或前端 setInterval 推断存在。

建议服务端每 30 秒发一次探测，收到当前实例/标签的确认才续租，租约 180 秒。后台但能确认的页面继续；冻结、睡眠或断连导致租约失效后暂停。页面 pagehide/freeze 提供尽力释放提示。最后一个有效页面的断连/释放被观察到后，立即停新步骤并进入 15 秒刷新/HMR 宽限；此时已有模型可继续，但不启动后续步骤。同一应用在宽限内重连可继续原在途任务，截止不延长；超过宽限即取消，后来重连不复活原任务。完全未观察到断连才采用 180 秒租约超时，失效后立即停派发并清理。最坏发现延迟为租约时长，不能承诺“关页瞬间 Node 一定知道”。超过宽限或租约失效后的恢复只从下个有效时段继续，不补跑离线时段。

### 调度一致性

- 仓库级单写所有权记录 instanceId、PID、进程创建时点与任务身份；第二开发服务拒绝接管同一研究目录。Vite 端口采用占用即失败，不能悄悄换端口。仅凭 PID 数字或陈旧文件不删除锁，必须核对旧进程身份。
- 用户可选间隔或每日若干 HH:mm，时区默认 Asia/Shanghai，并预览下一三次。保存配置带版本；在途任务封存旧配置，下轮应用新设置。多标签并发保存冲突返回明确提示，不最后写入无声覆盖。
- 定时槽以配置版本及 UTC 时段去重；手动调用以请求幂等键去重，两者共用全局在途锁。整队最多一个在途轮、每岗最多一个在途尝试，不为忙时请求增加队列。
- 周期短于研究时长时，明确记录“本时段因忙跳过”，完成后不马上补跑，只进入下个有效槽。时钟前跳不追赶，后跳不重复；夏令时缺失时段跳过、重复本地时段只执行一次。
- 暂停自动研究只阻止新轮；“取消本轮”单独取消当前进程。关闭最后页面按上一条租约契约取消。重新打开、服务重启都不自动续跑旧封存任务。

### 预算与停止

建议首版模型并发 2、每岗独立研究最多 3 次调用、全轮最多 20 次：五岗独立研究至多 15 次，保留首席与审核 2 次、一次定向补证澄清及重新综合/审核至多 3 次。补证为全队另计一次，具体边界见第4节；无补证预算则保留分歧。失败、超时和审核拒绝的实际调用同样计数，不用“重试”重置预算。开启模型轮前耐久预占该轮设定的日调用份额，份额不足则不启动模型轮，继续无模型检查；实际结束释放未使用份额。执行中始终保护首席与审核的保留量，不得给每个子步骤完整根预算。上下文按工具来源选择，模型输入初始上限 96 KiB，删减清单显式记录；关键证据不足就降级，不能靠无痕截断满足上限。

每次模型调用最多 8 分钟，整轮最多 60 分钟：第55分钟停止研究，预留最后5分钟用于精确进程清理和持久化收口。每次模型/HTTP/登录检查的截止不得超过本轮剩余研究预算；没有足够时间完成下一步骤就停止，不保证所有岗位都能用满三次。G0 根据实测调整预算或诚实部分交付。开发服务使用有进程树监督的启动器，单会话硬截止建议 8 小时，届时停止研究并显示需要重新开启开发服务。每项实际启动记录父子 PID、创建身份、开始、进度、截止与终态；Windows 隐藏窗口，不按进程名批量结束。

取消先为 cancelling，等待子进程退出并检查停止结果后才为 cancelled；单次精确停止动作最长10秒，余下清理窗口短观察核对。60分钟终点仍未确认清理则为 cleanup_uncertain，保留所有权、阻止新轮并展示精确任务身份；独立监督器继续有界检查，不把报告超时当底层进程已退出。根服务异常退出同样由监督器检查本次后代。浏览器睡眠恢复先执行截止/存活核对，不追加任务。运行上限是建议参数，G0 必须验证实际延迟和额度可承受性，不能据此承诺每几分钟一份报告。

配置提供每轮/本地日调用上限；每日调用默认建议 100 次并可下调，额度不够时仍优先停止。登录失效、模型不支持或真实额度限制分别暂停自动派发，人工恢复后再核对；不在每个时段反复撞限额。只有实际取得的用量/模型身份才显示，未知为“未取得”，不能写成零或猜模型。心跳不启动登录检查；认证检查有限缓存并接入同一取消信号和截止。

## 8. 产品页面、接口与持久化

首席决策台复用系统既定风格，先显示资料截止、当前解释、较上轮最多三项关键变化、证据强弱、主要分歧/反证、下一观察。下层是五领域覆盖和岗位摘要，可进入员工职责、当前问题、采用证据、观点历史及追问。工程调用记录折叠在诊断层；页面标题、空状态和主要按钮围绕研究内容。

`#/boardroom` 为首席决策台；`#/agent-chief` 指向同一入口；环境、盘口、衍生品员工页接真实报告，新增宏观与事件路由。原账户风险示意页保留诚实状态，不用改名冒充岗位研究。归档页读取不可变研究轮，可从每条观点打开当时证据和后续修订。用户追问沿用本次资料与版本，明确“回答历史问题”或“重新取证”，不会无声更新主报告。

设置页增加本地团队区：启停、节奏/时区、窗口偏好、调用上限、下一三次时间、最后成功/尝试、暂停原因及“现在更新/取消本轮”。与旧远程 D1 同步和模型退役说明分开；生产版不显示可启用的本地开关。初版五领域都覆盖，不增加任意 prompt、shell 参数或远程地址配置输入。

本地新接口建议 `/api/local-agent-team`，提供配置版本读写、纯状态、存在性确认、创建/取消、岗位和历史分页。保留 loopback、精确 Host/Origin、方法/JSON/字段/大小检查，正文总截止不只空闲超时；模型请求不能控制本地文件路径。服务端登记的工具回执与用户导入声明区分；哈希证明一致性，不认证来源真实性。模型子进程环境只保留必要变量，认证由官方 CLI 自己管理。

采用 Node 原子 JSON 与轻量索引，暂不新增数据库依赖。`.local/agent-team/` 保存配置、调度账本、岗位记忆、证据与不可变报告，拒绝静态访问。单文件原子替换不冒充多文件事务：调度槽、份额预占和调用意图先耐久写入权威运行账本，再启动进程；未取得退出回执的调用按已占用处理，重启不能重放该意图。报告/引用原件先落盘，再写接受提交标识，最后推进岗位指针与历史索引；只有提交标识可证明接受。指针与索引可从已提交原件重建，缺原件或哈希不符时隔离并停止该记录发布。创建耐久记录成功后才发布 active；关键保存失败停止新模型步骤并清理本次进程，不报告已保存。历史分页只读取索引，正文按需加载，进度事件合并有界写盘，任务缓存有上限。

进程重启将原在途尝试标 interrupted，保存部分证据；核对所有者与后代退出后才释放锁，不自动恢复调用。新执行器启用时，Vite 只注册一个研究执行器；旧 `/api/local-research/runs` 的创建、取消、续跑/重试等写入口返回退役状态，不启动模型或改写旧历史，历史 GET 不执行原来的恢复写盘。旧 `.artifacts/research-team` 回执只读兼容，不重新解释为新产品达标；云端生成端点和旧 CLI 队列继续退役。损坏记录隔离并显示错误，不覆盖原件；导出无凭据，保留引用、时间、配置与 prompt 版本。

## 11. 验收矩阵

行为结果用 PASS/FAIL/FLAKY；主观可读性/用途用 REVIEW。禁止以重试通过隐藏 flaky、未经确认更新视觉基线或用 synthetic 回执代替真实模型运行。

| 入口 → 动作/状态 | 必须观察到的结果与证据 |
| --- | --- |
| 团队 → 事件材料为空 | 零主张与明确缺口合法，其他岗位不被拖垮，无编造引用 |
| 盘口岗 → 只有 20 档快照 | 实际取得 book，价差/深度计算可复算；无连续挂撤单/订单意图结论 |
| 同一岗 → 两个不同研究缺口 | 工具、参数/窗口或停止决策合理变化并说明原因；保存模型请求与真实输出，不强制换工具 |
| 工具 → 非法工具/参数、恶意原文 | 请求被拒绝并有回执，原文指令不改变系统权限/研究任务 |
| 岗位 → 缺窗口、错单位、未收盘数据 | 结论降级或明确限制，数字核对失败不能进入有效主张 |
| 首席 → 三岗引用同一报道 | 视作同源证据，不提高独立证据数量；显示真实分歧和反证 |
| 原文 → 后续修订、公布时点未知 | 保留原版本/取得时点；无历史穿越或虚构发布时间 |
| 宏观 → 未到下一发布日 | 按日历/参考期判断，不因数值日期旧统一秒级判失效 |
| 岗位 → 第二轮市场变化/原判断纠正 | 观点父子版本及改判理由可追溯；方法变化另标 |
| 数据 → 无新资料、条件未到期/发现源失败 | 成功核对发现范围后才可无变化；新事件可被发现，检查失败不装无变化；旧报告生成时间不变 |
| 在途 → 新轮、迟到、取消后返回 | 终态/错轮结果不能污染当前；原尝试回执仍可追溯 |
| 单岗 → 超时或失败 | 其他岗可完成；首席明确部分覆盖、旧岗过期状态 |
| 当前页 → 行情更新而解读尚旧 | 同时显示行情与解读时点，不混成“实时结论” |
| 两标签/手动与定时 → 同时触发 | 只有一轮在途、幂等返回；多标签一致显示状态 |
| 第二开发服务 → 同目录启动 | 拒绝接管/改写首实例在途记录，无重复额度调用 |
| 后台/切页/刷新 → 14秒与16秒重连 | 站内切页保持存在性；14秒可继续原任务，16秒不得复活已取消尝试；不重复派发 |
| 最后页面关闭/冻结/睡眠 → 租约到期 | 停新调用，执行精确进程清理；恢复不补跑旧槽 |
| 设置 → 在途改节奏/并发保存 | 当前配置封存，下一轮应用；冲突提示与下一三次时间准确 |
| 调度 → 研究慢于周期/时钟前后跳/DST | 忙时跳过，无队列爆发；同槽不重复、不补跑 |
| 模型 → 登录/额度不足或能力不支持 | 自动派发暂停，原因可核对，无付费/第三方回退；未知用量不填零 |
| 预算 → 岗位用满/日仅余1次/审核拒绝 | 补证上限明示，实际失败调用计数；保留首席/审核量，日份额不足不开模型轮 |
| 取消/根崩溃 → 子进程仍存在 | 状态不提前报已停止，精确 PID 清理；不确定时阻止替代任务 |
| 第55/59分钟 → 模型仍运行/停止失败 | 停止新研究并清理，60分钟未核对退出保留锁与 cleanup_uncertain |
| 存储 → 创建/进度写失败、损坏历史 | 无幽灵 active，无虚假保存成功；原件保留、可见错误 |
| 存储 → 预算预占/原件/提交/索引间崩溃 | 不重放调用意图，不漏记份额，不发布未提交报告，索引能重建 |
| 旧创建/重试接口 → 新执行器已启用 | 明确退役，不启动模型或改写旧记录，读历史仍可用 |
| 本地 API → 跨源/非法 Host/慢请求/超限 | 有界拒绝；现有私密目录不暴露，模型不控制路径/命令 |
| 首席、员工、历史、设置 → 真正操作 | 可进入证据、查变化、保存节奏、暂停/取消；桌面/移动/主题无阻断 |
| 同材料对照 → 阅读首席与基础摘要 | 无关键来源/数值错误；反证、解释依据、下一核查具体；记录阅读理解与时间，REVIEW 不冒充量化预测优势 |

程序验证复用 `npm run lint`、`verify:team`、`verify:research`、`verify:evidence`、`verify:finance`、`verify:yuqing`、`verify:research-ui`，新增实际工具/调度/跨轮反例测试。最终实现运行 `npm run build`，确认 `dist/pages/` 与开发运行能力边界。使用项目可重复 Playwright 脚本采集目标交互、console/network、必要截图与 trace；人工语义探索辅助，不用坐标点击作为正式验收。
