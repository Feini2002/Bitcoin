# 比特币合约系统对标与基础数据层复审

查询与源码核对日期：2026-09-30（北京时间）。本记录回答：现有数据是否齐备、应参考哪些成熟项目、参考之后是否需要调整数据架构。本轮只沉淀研究与验证反例；下文建议尚未实施。当前开发仍以[四页方案](repository-development-plan-2026-09-27.md)为入口。

## 1. 直接结论

1. **主要基础链路已建立，但不能说“所有该接的数据都接齐了”。** 当前代码有 33 项规范数据集，另有足迹、分所强平和遗留衍生品表；33 是数据集数，包含七个 K 线周期，不是 33 个独立来源，也不是 33 项实时健康承诺。Binance USDⓈ-M BTCUSDT 的分钟级至波段观察已具备主要输入。
2. **不需要因为发现优秀仓库就推翻部署骨架。** 保留 Pages、Workers、单常驻采集器、东京出口和 D1 窗口读取。优秀案例支持统一产品身份、可核验事件与回放、确定性计算、来源和时间约束；它们并不证明本项目必须迁库、部署整套机器人或引入 Kafka。
3. **数据接口与研究证据仍值得局部改进。** 已复现部分输入版本号不随内容变化。开始多角色研究前，应固定一份具有截止时间、各来源版本和限制的证据包；做长期回测或连续盘口研究时，再增加原始事件归档和深度流。跨所衍生品、期权、ETF、链上属于按研究目标补齐的覆盖，不宜与普通页面可用性混为一谈。

建议次序：内容版本完整性 → 研究证据包与历史时点边界 → 明确研究场景后扩来源及原始留存。成交长历史先核验可利用的币安官方归档，不把 REST 窗口限制当作全部历史不可恢复。具体范围、代价与验收见[采用方案](contract-system-cases-2026-09-30/adoption-plan.md)。

## 3. 现在的数据层实际覆盖

主要路径：交易所／宏观来源 → 东京出口或 Worker 直连 → 采集器与按频率调度 → 原始市场表／规范观察与采集状态 → 四个 desk 读口 → 页面、导出与人工研究证据。

| 范围 | 已有源码与契约 | 覆盖边界 |
| --- | --- | --- |
| 永续行情 | Binance BTCUSDT 七周期；原始 K 线与规范证据有界合并、缺口与收盘资格、历史修订通知 | 主市场固定为 Binance USDⓈ-M；更长原始历史不等于逐棒来源已核实，旧原生 3d 异常仍须保留 |
| 合约基本面 | 标记价／指数价／报告费率、已结算资金费、OI 与小时 OI、主动量、账户比、头部持仓比、基差、规则与费率调整 | 大部分为单所；账户比不是仓位，OI 不是净流入，报告费率不是新结算事件 |
| 现货背景 | Binance 现货 1h K 线 | 不是完整现货逐笔、跨所价格发现或 CME 期货输入 |
| 足迹与成交 | aggTrades 聚合为 5m 价位桶；其他足迹周期读取时合成 | 基础桶以 1 USDT 归并，最多 8640 根；没有完整原始逐笔长期磁带，不能还原桶内成交顺序或任意更细价档 |
| 盘口 | REST 20 档快照、更新 ID、独立来源与收据 | 不是连续深度流；没有证明可以逐事件重建挂撤单、流动性迁移或队列位置 |
| 强平 | Binance 与 Bybit 实际收到的流，按交易所存 5m 桶，30 日保留 | 原始事件未持久化；币安公开流为采样快照，停采历史不能补造，分所金额／笔数不能当完整全市场口径 |
| 期权 | Deribit 原生摘要规范集，每 6 小时，保留最近 8 次收据 | 不等于连续完整期权链、可成交波动面或已验证 25-delta/GEX。遗留 surface 表存在也不证明当前已持续采集、接入 desk |
| 宏观 | FRED 九序列、SOFR，区分日／周／月频和来源观察时间 | 既有系统收据不等于最初公布时间；首次导入的最新修订不能反推当年已知值；部分来源曾陈旧 |
| 加密背景 | 稳定币供应、CoinGecko 广度、mempool 费率 | 供应不是交易所净流入，网络费不是链上资金流；独立 ETF 申赎、交易所链上流、矿工／持币结构未进入这 33 项规范集 |
| 新闻与事件 | 舆情事实、历史报告与人工研究协议 | 不代表完整社媒样本、持续全文档案或所有历史可回放；无覆盖不能解释为“没有事件” |
| 历史时点 | 规范观察有 received/stored/source revision，部分读口有 knownAt | 是系统实际见到的数据约束；不覆盖未保存的旧逐笔／旧盘口，也不自动证明历史时点采集健康 |
| 研究输入 | 页面事实导出、研究 CLI 保存多个 desk 响应 | 每个响应可检查，但目前并非具有统一截止和完整内容版本的冻结数据产品 |

关联源码：cloudflare/finance/datasets.mjs、dataset-store.mjs、dataset-schema.sql、scheduler.mjs、desk.mjs；cloudflare/schema.sql、binance-klines-worker.js、kline-live-collector.mjs；js/workbench-evidence.js、research-protocol.js；scripts/research/prepare-research.cjs。

规范 K 线保留为 5m 900、其他周期 600 根；原始 K 线最多 6000 根，不能把二者混用。盘口保留 720 条观察，premium/OI 为 3600 条，实际时间跨度取决于成功采集节奏。本轮核对的是源码政策，没有查询全量远程库存。

## 5. Review 发现与证据强度

### R1：部分输入版本不覆盖实际内容

**已复现的源码事实：** 固定时间与来源，调用当前真实 desk 装配函数，改变下面的合成数据，输出值变化而输入版本号相同：

| 读口 | 改变的事实值 | 输入版本结果 |
| --- | --- | --- |
| 强平 | 同一币安桶 longNotional：100 → 1000 | 相同 |
| 订单流 | 同桶 Delta：10 → −40；volume：100 → 150 | 相同 |
| 环境背景 | 同观察日 FRED 2y 值：4 → 5 | 相同 |

原因：强平版本仅包括交易所名单；订单流主要包括最新成交时间与成功状态；背景版本主要包括 premium/funding/basis 的观察时间，未覆盖宏观和持仓等完整事实。K 线已有更完整的内容及历史修订体系，不应重做。

**影响判断：** 这些版本不能单独作为“输入完全相同”的证据。若后续研究去重、缓存失效、报告追溯或多 Agent 共用它们，会漏掉数据变化。本轮没有证明现有页面已经因它们漏刷新；已查的主要前端路径未发现直接以这三个版本作刷新开关。优先完善接口语义，而不是宣称所有页面数值错误。

原始反例与可复现脚本见[反例结果](contract-system-cases-2026-09-30/evidence/input-revision-counterexamples.json)、[复现文本](contract-system-cases-2026-09-30/evidence/reproduce-input-revisions.mjs.txt)。全部为固定合成输入，无远程数据修改。

### R2：人工研究准备还没有冻结跨范围输入

prepare-research 保存六个并行 GET 的响应，并记录各自读取时间；这比模型自己抓数据更可追溯。但 capturedAt 是采集完成时间，图表有闭合边界，其他实时范围并未统一为同一个知识截止；没有完整的范围版本清单与冻结内容 ID。

这是开始重复研究／多角色运行时应补的接口：保存各来源实际观察、接收、首次可知／未知、范围及内容摘要。统一截止不等于强行让秒级行情和周频宏观拥有同一观察时间。失败、未知和覆盖空洞必须随证据包进入研究。

### R3：原始市场回放与当前聚合层是不同能力

市场 schema 明确仅保存强平 5m 桶，足迹保存价位聚合，盘口是短期 REST 快照。聚合不可逆；不能靠升级 Agent 或再运行今天的 REST 恢复过去的事件顺序。

**成交历史有独立补源候选。** 币安官方日／月归档包含合约 aggTrades；本轮对 2024-07-04 BTCUSDT 文件的 HEAD 与 CHECKSUM 的 GET 均返回 200，当前未发现业务已接归档适配。这纠正“REST 窗口之外足迹一概不可补”的推断。未下载 ZIP、验证 CSV 或实际补洞；归档修订、语义缺口及历史首次可知时间仍须处理。详见[官方历史归档核验](contract-system-cases-2026-09-30/official-history-archive.md)。

若目标只是现有窗口观察，可保留这种边界；若目标变为订单簿研究、跨所价格发现、多年逐笔回测或方法重算，则需要旁路原始事件／快照及连续性清单。它是新增能力与费用取舍，不是本轮已完成的修复。

### R4：覆盖扩展应服从问题，不按接口数量扩建

- 做“币安全市场代表性”判断时，多所 OI／费率／基差与现货对照需要新增独立序列；当前 Bybit 强平不替代 Bybit OI。统一单位后仍保留交易所、线性／反向和结算币差别。
- 做期权波动结构时，摘要不足，需要按到期／行权价／类型保存 instrument、报价、标记 IV、Greeks 与时间。mark IV、可成交 IV 与 GEX 假设分开。
- 做 ETF／链上资金研究时，需独立的原始披露／实体标签与修订血缘；新闻、稳定币供应和 mempool 费率不充当资金流数值。

这些方法会扩大来源、保留或费用；先选定具体研究问题和验收，再实施。不以数据字段“看起来很多”判断齐全。

## 6. 是否更换数据层架构

**保留部署结构，调整证据契约；扩展原始存储时采用旁路。**

建议结构：现有采集适配与 DO 调度 → 规范观察／质量／聚合 → D1 有界读口 → 冻结研究证据包 → 确定性计算与按需人工／多角色研究。原始事件归档在采集后并行写入对象／列式文件，输出连续性与校验清单，由复算程序回到同一规范模型；不让浏览器查询扫完整磁带。

R2 或其他对象存储、Parquet 目录是条件候选，尚未采购、创建或绑定。Cloudflare 最新官方说明 D1 付费单库最高 10 GB，单库查询串行处理；这说明逐事件无限写入必须量测，但没有测得本项目当前容量或持续吞吐不足，不能据此立即迁库。[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)

不建议此时更换前端框架、拆全套微服务、替换已修复的图表读取链路，或为多个 Agent 再建多个重复采集器。多 Agent 共用冻结输入、独立提出证据与反证；是否提高研究质量要在相同输入、预算和评价标准下对照。
