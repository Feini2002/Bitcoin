# 比特币金融分析系统：证据核验、研究纠偏与能力升级报告

**核验日期：2026 年 9 月 16 日，Asia/Singapore。**
**交付性质：公开资料研究、条件化能力建议和实施前仓库核验材料。**
**执行边界：未读取实际项目仓库；未安装软件、运行候选代码、接入账号、调用交易接口或操作生产系统。**

## 1. 执行摘要

**核心结论：最值得吸收的是“可核验的数据语义、可复现的研究过程、可追证的报告和可恢复的研究工作区”，不是某套新技术栈。当前应以局部演进为默认选项；只有具体任务证明现有部署不合适，才增加专用数据或计算服务。**

本轮保留上一版关于时间口径、数据修订、授权分层和不默认自动交易的主要判断，但修正了三个重要倾向：过早将混合架构设为首选、“值得试验”范围过宽，以及把阅读发布页的证据标签与维护成熟度放在同一列。

最终只建议开发者讨论五项能力：

| 编号 | 能力，而非采购清单 | 新增研究价值 | 当前判断 |
|---|---|---|---|
| A | 数据、指标和报告的版本化证据链 | 能回答“这个数从哪里来、当时能否知道、为何后来改变” | **优先考虑**；现有机制成立就复用，不另造一套 |
| B | 有来源口径的订单流与衍生品分析 | 区分主动成交、持仓、清算事件和清算估计，分析价格变化伴随的杠杆与流动性条件 | **先做小实验**；不默认全市场、全深度采集 |
| C | 时点正确的事件与跨资产研究 | 比较宏观、ETF 等事件前后表现，区分相关性、修订影响与可重复模式 | **优先考虑方法**；先选一个问题，不同时接齐所有数据 |
| D | 证据约束的 LLM 报告与回归评估 | 减少数字、引用、窗口和权限错误，检验模型是否比模板真正有用 | **优先考虑**；保留已有云端执行方式的可能性 |
| E | 图表—事件—证据—笔记联动与可解释预警 | 减少来回查找；能恢复一份历史报告对应的研究现场 | **局部试验**；先增强现有页面，不先替换图表 |

DuckDB、CCXT、vollib、arch、promptfoo 等是其中某个环节的候选，不是五项能力的必装依赖。是否需要独立服务、哪种语言承担计算、是否迁移数据库，仍取决于仓库事实。

**本轮最重要的新证据：**同名字段可能代表完全不同的经济含义；专业产品里的足迹也可能是估算而非直接主动成交；上游历史文件可能被替换；公共 API 不等于允许公开分发衍生报告。这些问题对分析质量的影响，比更换前端框架更直接。具体依据见第 2、5 节。

## 2. 本轮纠偏发现与修正

### 2.1 对上一版的逐项审查

上一版已经明确了未读仓库、未运行验证、数据授权独立等边界，因此不能把所有潜在偏差都认定为已发生的问题。其 R/D/S 分类实际表达的是“看过发布记录、看过文档、服务文档可读”，不应被继续当作维护健康度。

| 审查项 | 实际发现 | 本版处理 |
|---|---|---|
| 1. 热门项目、首页偏差 | 无法仅凭成文报告证明检索只停留首页；但专用统计、期权计算和报告测试工具覆盖偏弱 | 补查 arch、ruptures、vollib、promptfoo，以及交易所和产品的方法文档 |
| 2. Star、宣传、最后提交代替成熟度 | 未发现按 Star 排名；维护标签和部分维护者集中度描述仍缺可比依据 | 将能力证据与维护判断分开；不明的维护强度和响应能力标“未知” |
| 3. 工具多、流程弱 | 已有能力组合，但候选和“值得试验”过多，难形成开发决策 | 收敛为 A—E 五项能力，每项给出最小链路和放弃条件 |
| 4. 有功能等于适合场景 | 一些“推荐采用”仍领先于兼容性、数据质量和使用收益验证 | 推荐机制优先于推荐依赖；组件必须有竞争性替代 |
| 5. 偏向换架构 | 没有要求推倒重写，但将 B 混合路线设为条件性首选，仍容易形成锚定 | 未知仓库下默认 A 路线；高频、计算和运维条件成立才选 B |
| 6. 职责重复 | 多套采集、图表、计算、代理和调度框架均进入试验池 | 每层设默认方案、一个主要替代和引入触发条件 |
| 7. 免费与受限数据混淆 | 上一版总体有区分；但缺少部分直接数据条款和端点级历史覆盖 | 补 Coinbase、Deribit、Tardis 细则；删除不帮助决策的泛套餐报价 |
| 8. 历史、修订、时间口径 | 并未忽略；但对归档替换、来源聚合差异、读副本语义覆盖不足 | 加入摄取版本、真实可见时点、上游修订和跨端点不可等同的检查 |
| 9. 估计当观测 | 已区分链上标签；清算热力图和估算足迹的产品差异仍不足 | 明确“成交观测、盘口观测、清算观测、模型估计”分层 |
| 10. 授权与维护代价 | 已有大量授权检查，但 Binance 许可状态和 Tardis 适用范围需要修正 | 见下节；代码、数据、外部推理、分发分别审批 |
| 11. 无依据精确结论 | 未发现实际吞吐或工期承诺；精确版本和套餐数字过多，却未固定证据快照 | 只保留影响决策的版本、协议数值和官方限额；不声称锁定最新版本 |
| 12. 文档、源码、运行混淆 | 没有声称运行成功；部分源码路径、方法页定位还不够具体 | 重点候选给直接方法页或源码路径，并继续声明未执行 |
| 13. 未查仓库写成事实 | 未发现需要撤回的明确仓库故障诊断 | 保留条件表达；不虚构文件名、函数或缺失能力 |
| 14. 不利证据不足 | 已有退出条件，但对轻量保留方案、数据条款和估算产品的反例不足 | 把不采用条件纳入每项能力，保留对推荐不利的证据 |

### 2.2 实质性修正，不只是调整措辞

**第一，修正 Binance 归档许可判断。** 当前 [binance-public-data README 的 Licence 节](https://github.com/binance/binance-public-data#licence)明确声明 MIT；上一版“未确认明确授权”的表述应缩小为：独立 LICENSE 路径本次返回 404，但 README 的 MIT 声明已经找到。该声明不能单独完成交易所 API、数据商业展示、再分发及第三方使用权审查。

**第二，修正“原始文件不可变”的适用对象。** 同一 README 明示归档可能因发现问题而替换，并提供校验和变更记录。因此应保证的是**本系统已摄取版本不被无痕覆盖**，不是假设上游文件永不改变。校验和只能帮助确认文件一致性，不能证明市场事件完整。

**第三，补齐 D1 的反面证据。** [D1 限制](https://developers.cloudflare.com/d1/platform/limits/)仍包括付费单库 10 GB 等边界，但单线程处理描述针对各数据库实例；[读副本与 Sessions API](https://developers.cloudflare.com/d1/best-practices/read-replication/)提供另一条扩展读服务的路径。不能从“D1 一次处理一个查询”直接推出整个系统必须迁移；读副本也不能解决所有写入或扫描问题。

**第四，修正 Tardis 条款的适用范围。** [条款 9.5](https://docs.tardis.dev/legal/terms-of-service)对通用 AI/LLM 相关用途和外部披露设有限制，但 9.6 又明确区分开源 SDK 与供应商数据：通过软件独立从交易所取得的数据，不会仅因为使用该软件就自动适用 Tardis 的供应商数据限制。普通云端推理能否获准仍需按具体用途确认，不能一概判为允许或禁止。

**第五，修正足迹图的定义。** [TradingView 中文方法说明](https://cn.tradingview.com/support/solutions/43000726164/)明确存在按较低周期价格方向分类成交量的方式，并提示历史粒度变化和重绘。因此，估算足迹可以作为产品能力，但不得标成直接观测的主动买卖成交；本系统需要保存分类方法和粒度，而不是仅看“Footprint”名称。

**第六，撤下无法独立复证的瞬时案例。** 上一版关于 Farside 某日“部分明细缺失、合计为零”的页面状态没有附归档快照。本轮不再将该具体历史状态当作已核验事实；保留“未知不等于零、明细未到齐不能认定完整”的规则，并在实验中使用明确标注的合成样本。

## 3. 已知背景、研究边界与证据说明

### 3.1 四种证据标签

| 标签 | 本报告的严格含义 |
|---|---|
| **已核验事实** | 由本轮读取的官方协议、许可证、发布记录、源码片段或论文页面直接支持；不包括本仓库情况 |
| **合理推断** | 从上述事实及“个人或小团队维护”的假设推导出的设计建议；可以被仓库证据推翻 |
| **待验证假设** | 必须查代码、样本或运行隔离实验后才能确定的兼容性、负载、质量或收益 |
| **未知** | 当前没有足够证据，包括未取得的数据授权、完整维护者分布、实际 SLA 和成本 |

下文的能力方案、验收条件和优先级均属于**建议或合理推断**；来源字段、许可证和官方限制标为**已核验事实**。没有标为事实的架构图，不应被理解为现状图。

已知背景仅来自用户：系统围绕 BTC 分析，涉及图表、指标、足迹、订单流、宏观、舆情及云端 LLM；技术包括 HTML/CSS/JavaScript、Cloudflare Pages/Workers/D1；来源包括 Binance、Deribit、FRED、Yahoo；项目暂停。具体实现、版本、数据量、成本、可用性和缺陷均未知。

### 3.2 本轮检索与访问边界

本轮完整阅读了上一版 Markdown，并重新检索公共 GitHub、交易所文档、Cloudflare 文档、软件许可与发布页、发行人披露、学术论文页面，以及中英文产品方法说明。检索重点从“还可以接什么平台”改为“哪些证据会推翻原推荐”。

社区方面实际读取了 [Reddit 历史盘口讨论](https://www.reddit.com/r/algotrading/comments/nz5lnl/binance_full_or_atleast_sufficiently_deep/)及一条 [Hacker News 工作流讨论](https://news.ycombinator.com/item?id=41039204)，只用于发现历史覆盖和框架生命周期问题，不据此认定当前产品质量。中文资料包括 KLineChart 官方文档、TradingView 中文计算说明及中文产品/社区检索结果。部分搜索结果只落到首页或摘要，未计入已读正文。

X 命中的 CoinGlass 帖子正文本轮访问失败；部分 CCXT/AI SDK 网页入口也失败，后者已用可读源码或其他官方页面补证。没有访问私密社区、付费终端、登录后的账号数据，也没有下载市场数据来验证接口表现。

**维护判断规则：**“成熟稳定”指接口与用途相对明确、存在维护和兼容性证据，不等于无缺陷；“活跃演进”指可见实质更新，也可能意味着升级负担；“维护有限”必须有相应证据。仅未找到最近提交，不足以认定停止维护。本轮没有充分证据将重点候选判为停止维护，部分项目保留“维护强度未知”。

## 4. 方案地图与候选项目表

### 4.1 以研究流程组织边界

建议的逻辑链是：

**研究问题 → 获准来源 → 采集/回补 → 标准化与质量 → 版本化数据 → 确定性计算 → 查询 API → 图表/事件/报告 → 可复现验证。**

这是一条职责链，不要求每个箭头都部署一个服务。一个现有 Worker、一段批处理或一个模块可以承担多个职责，只要数据和版本边界清楚。

| 研究环节 | 首先考虑的最小复用 | 升级触发，不是默认配置 |
|---|---|---|
| 多源适配 | 保留可靠原生适配；重复接口多时试 CCXT | 多所高频接入已成为主要维护负担时比较 Cryptofeed |
| 历史与分析存储 | 当前存储＋版本清单；需要文件扫描时试 Parquet/DuckDB | 实测持续并发或写入需求超出后，再比较在线分析库 |
| 期权计算 | 交易所快照与明确报价筛选 | 需要独立计算校验时试 vollib，不先引入完整定价平台 |
| 事件与因子验证 | 固定数据、预声明窗口、简单统计 | 存在序列相关和不确定性估计需求时试 arch |
| 市场状态 | 先用可解释、只读过去数据的规则 | ruptures 先用于离线复盘，不直接输出实时状态 |
| 图表与工作区 | 现有图表加证据入口、共享窗口和笔记 | 真实交互任务受限时才比较 Lightweight Charts/KLineChart |
| 报告与评估 | 现有模型适配＋程序校验＋模板基线 | 多模型回归和测试管理困难时试 AI SDK/promptfoo |
| 调度 | 现有定时入口、任务账本和幂等 | 真有长流程恢复/缓冲需求时采用 Workflows 或 Queues |

| [IBIT 发行人披露](https://www.ishares.com/us/products/333011/ishares-bitcoin-trust-etf)＋[Farside](https://farside.co.uk/btc/) | ETF 来源与交叉核对 | 服务/数据条款分别审查；无统一免费再分发保证 | **推荐核对流程** |
| [Circle](https://www.circle.com/transparency)、[Tether](https://tether.to/en/transparency/) | 稳定币发行人披露 | 公开页面不等于完整历史 API 或再授权 | **先做语境数据** |
| [CoinGlass 热力图 API](https://docs.coinglass.com/reference/liquidation-aggregate-heatmap) | 模型化清算位置估计 | 商业模型，非真实持仓全量观测 | **仅作估计层备选** |

表中软件许可和维护判断依据下节直接资料；数据服务“文档可读”不等于服务经过可用性验证。

## 5. 重点候选的深度比较

### 5.1 原生交易所协议：先核经济含义，再选采集框架

**已核验事实。** 下列差异足以影响 CVD、清算额和历史比较，不应被统一字段名掩盖。

| 来源/接口 | 直接证据 | 对本系统的具体影响 |
|---|---|---|
| Binance Spot trades/aggTrade | [WebSocket 协议](https://raw.githubusercontent.com/binance/binance-spot-api-docs/master/web-socket-streams.md)：`m` 表示买方是否 maker；aggTrade 按单个 taker 订单聚合；实时可选择微秒 | 主动方向需转换；实时并非永远毫秒；不能将 trade 与 aggTrade 相加 |
| Binance USDⓈ-M aggTrade/盘口 | [市场流 Aggregate Trade Streams](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market)：同价格、同方向按 100 ms 聚合；`q` 与 `nq` 的 RPI 口径不同。[Order Book](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)不含 RPI 订单 | 现货与合约 aggTrade 不应假定同义；成交与可见盘口不必逐项相等 |
| Binance OI 统计 | [Open Interest Statistics](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)：最近一个月；时间戳为统计期末 | 不能补出任意多年 OI；不能按 K 线开盘时间无条件连接 |
| Binance 清算流 | [All Market Liquidation Order Streams](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market)：每交易对 1,000 ms 窗口最新一条 | 应称“该流观测清算”，不能宣称完整清算量 |
| Bybit allLiquidation | [频道源码](https://raw.githubusercontent.com/bybit-exchange/docs/master/docs/v5/websocket/public/all-liquidation.mdx)：文档描述 500 ms 推送全部清算；`S` 为被清算持仓方向，`p` 为破产价 | `Buy` 不是主动买入成交；破产价不等于实际成交价；文档完整性承诺不证明本地从未丢包 |
| Coinbase match | [Match 节](https://docs.cdp.coinbase.com/exchange/websocket-feed/channels)：`side` 为 maker 方向 | 与以 taker 方向定义的 CVD 需要反向映射 |

以上来自官方字段与方法说明，未通过本轮运行验证。

**复用与环境。** 原生只读适配可继续用现有 JavaScript；持续采集才需要评估长期进程。协议适配的替代是 CCXT，但来源语义的最终依据仍是交易所。需要保存原始 payload、频道、instrument 规格、聚合方式和适配器版本，不只保留统一后的 `price/amount/side`。

**权利与维护。** 服务的代码许可不适用；数据条款适用。特别是 [Coinbase Market Data Terms](https://www.coinbase.com/legal/market_data)将对组织外分发的数据、图表、分析和研究等衍生作品列入书面同意范围。Binance、Bybit 对具体产品用途的完整授权本轮未核全，不因接口公开而放行。官方文档可维护不代表个人能获得 SLA。

**取舍。** 先做一个已用市场的语义测试，再考虑第二市场。若现有适配已正确且覆盖足够，保留它比换采集器更合理。新增来源应证明提供了独立市场信息，而不是仅增加面板数量。

### 5.2 CCXT 与 Cryptofeed：统一接口的收益，要抵过新的适配层

**CCXT。已核验事实：**[MIT 许可](https://raw.githubusercontent.com/ccxt/ccxt/master/LICENSE.txt)；[发布记录](https://github.com/ccxt/ccxt/releases)可见持续适配修正；[源码 `ts/src/binance.ts` 的 `parseTrade`](https://github.com/ccxt/ccxt/blob/master/ts/src/binance.ts)包含多个来源形态和 maker/taker 解析。它能减少普通行情接口适配，但不是免费历史数据服务。维护判断为**活跃演进，具体交易所适配质量待验证**。

适合直接依赖于已有兼容运行环境；Workers 中能否使用所需方法、包体和网络模式必须验证，不能由“支持 JS”推出。免费代码不免除上游 API key、限流、历史深度和再分发限制。最低实验是用同一原始样本对照现有解析与 CCXT 输出，不先迁移全部来源。

**竞争替代：原生小适配。** 只接一两个来源且当前代码可靠时，原生方式少一层版本漂移；多所重复工作明显时，CCXT 更有吸引力。

**Cryptofeed。已核验事实：**[CHANGES](https://raw.githubusercontent.com/bmoscon/cryptofeed/master/CHANGES.md)记载 2.5.0 的 Python/CI 和字段修正，主分支 3.0 涉及异步核心和移除 REST；[当前许可](https://raw.githubusercontent.com/bmoscon/cryptofeed/master/LICENSE)为 AGPL 并有附加署名。主分支变更不等于已确认稳定发行。维护判断为**活跃演进、迁移风险明显**。

它适合多个持续实时流，但会增加 Python 运行环境、连接恢复和版本回归责任。独立服务并不自动解除许可义务。**本轮不把它列为默认引入项**；只有实时多所采集已经是核心维护负担、许可可接受且明显优于原生/CCXT 时再试验。

### 5.3 Deribit 与 vollib：先确保快照可解释，再独立校验期权计算

**Deribit，官方数据服务。已核验事实：**[`get_order_book`](https://docs.deribit.com/api-reference/market-data/public-get_order_book)提供报价、mark、IV、Greeks 等字段，并明确 OI 产品间单位差异；[`get_book_summary_by_currency`](https://docs.deribit.com/api-reference/market-data/public-get_book_summary_by_currency)可用于获取汇总截面。[采集最佳实践](https://docs.deribit.com/articles/market-data-collection-best-practices)说明 raw 公共流需要认证，极端负载还可能有合并；[限流文档](https://docs.deribit.com/articles/rate-limits)对不同方法设有不同成本，不能套一个统一请求频率。

最小复用是公共快照/API，不是立即订阅全部 raw 频道。快照批次应记录每个合约的时间、采样跨度、报价缺失和产品状态；分批拉取的截面不是严格同一瞬间。公开端点可读不保证多年期权链历史免费可得，具体保存、商业分发和外部模型用途仍**未知**。

维护判断为**官方协议持续维护，运行可靠性未测**。替代是 Tardis 等获授权历史源：自采适合从现在积累，采购适合回答过去问题。若只需要当前市场概览，采购多年全量盘口并无必要。

**vollib，专用数值库。已核验事实：**[官方仓库](https://github.com/vollib/py_vollib)说明 Black、Black–Scholes、Black–Scholes–Merton 的价格、IV 和 Greeks；[MIT 许可](https://raw.githubusercontent.com/vollib/py_vollib/master/LICENSE)；[源码 `vollib/black/implied_volatility.py`](https://github.com/vollib/py_vollib/blob/master/vollib/black/implied_volatility.py)明确函数输入是折现期权价格、远期/期货价格、行权价、利率和以年计到期时间。

它的价值是独立复算和误差诊断，不是替代交易所产品规格。BTC 计价、结算币、合约乘数和报价转换必须先完成；不能把一个币本位报价直接塞入普通美元 Black 模型，也不能把 OI 当成交易商净 Gamma 的真值。

运行在 Python 科学计算环境，软件本身免费、不含行情；额外代价是数值样本、依赖和模型假设维护。项目存在命名/命名空间迁移，**维护强度和新旧包兼容性未知**，不因熟悉旧名称就认定版本可用。

**竞争替代：直接展示来源 IV＋质量标签。** 没有独立复算问题时它更便宜；需要复杂支付结构时才另评更完整定价库。vollib 仅列为实验依赖，验收看价格—IV 往返、边界异常和同约定报价对照，不要求盲目匹配供应商 mark。

### 5.4 Tardis：购买缺失历史，不购买“事实完整性保证”

**已核验事实：**[Deribit 历史说明](https://docs.tardis.dev/historical-data-details/deribit)声明覆盖从 2019-03-30 开始的所有 instrument，包括期权，并要求结合 symbol、channel、日期和事件目录检查覆盖。这是供应商声明，不是本轮验证过每个文件完整。SDK [MPL-2.0 许可](https://raw.githubusercontent.com/tardis-dev/tardis-node/master/LICENSE)与[套餐/历史权限](https://docs.tardis.dev/faq/billing-and-subscriptions.md)分离；CSV、原始回放和可访问历史不能混为一个免费能力。

复用方式可以是文件导入或独立 Node SDK，不必改变前端。实际 Node 要求按锁定发行核查，本版不把上一版默认分支 manifest 当成部署基线。维护判断为**服务与 SDK 资料持续可用，SDK 发行健康度、服务 SLA 和实际缺口未知**。

[服务条款第 9 节](https://docs.tardis.dev/legal/terms-of-service)是接入前关口：内部使用、衍生输出、外部供应商、通用 AI 相关用途分别判断；第 9.6 节避免把独立直采数据误归为供应商数据。派生后不能重建原始数据，也不自动等于所有用途已获许可。

**竞争替代：原生归档＋从现在自采。** 没有原生历史 L2 时，自采只能积累未来，不是对过去的等价替代。先明确一个过去事件及必要字段，再取得样本、覆盖清单和适用报价；没有可接受授权、预算或研究问题时停止采购。套餐价格不作为当前系统总成本估算。

### 5.5 DuckDB＋Parquet：批处理工具，不预设新增在线数据库

**已核验事实：**DuckDB [MIT 许可](https://raw.githubusercontent.com/duckdb/duckdb/main/LICENSE)；官方支持 [Parquet 查询及读写](https://duckdb.org/docs/current/data/parquet/overview.html)和 [R2 访问](https://duckdb.org/docs/current/guides/network_cloud_storage/cloudflare_r2_import.html)。其[当前并发文档](https://duckdb.org/docs/current/connect/concurrency.html)区分进程内读写、只读多进程以及其他远程/目录方案，不能概括为“永远不支持多个进程写”，也不能把普通数据库文件直接当共享写服务器。

**合理推断：**对于有限市场、定时研究、可预计算页面，先用一个受控批处理读取分区文件，通常比先部署在线分析服务更容易验证。它可以按任务启动，不要求 24 小时常驻；已有磁盘或对象存储可先复用，R2 不是必要前提。

维护判断为**成熟组件持续演进**，[发布记录](https://github.com/duckdb/duckdb/releases)和版本化文档可见；本轮未做性能测试。Node/Python/CLI 的具体包与运行环境分别核查，不把原生扩展可用性投射到 Workers。

**代价与替代：**文件分区、小文件合并、数据版本、扫描预算和故障重跑仍有人负责。竞争替代首先是**现有 D1/SQL＋预计算**，不是直接 ClickHouse。只有反复在线查询、多用户并发或持续写入的实测需求成立，再比较服务型数据库；两条路径结果一致，比某个厂商 benchmark 更重要。

### 5.6 FRED/ALFRED：时点规范明确，但不能补出不存在的发布时间

**已核验事实：**[real-time period 文档](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)说明默认查询与历史版本的差异，参数以日期表达；[使用条款](https://fred.stlouisfed.org/docs/api/terms_of_use.html)并不覆盖第三方序列的所有数据权利。

适用问题是“某次历史报告截止前，究竟可见哪个版本”，复用方式是 API＋版本化存储。JS 可直接处理请求，统计任务再选择运行环境。免费 API 访问不等于所有序列均可商业再分发，也不等于无限调用或 SLA。

维护判断为**稳定官方服务与规范，具体序列覆盖需查**。竞争替代是原始统计机构/央行的发布档案；对精确日内事件研究，原始发布时间有时比聚合序列的日期更重要。

**不采用条件：**目标序列没有足够历史 vintage 或可信可见时间时，不做声称“当时可执行”的历史研究；可以降级为当前宏观描述。第三方序列权限未清楚时，不进入公开导出和云端模型输入。

### 5.7 arch：给事件研究增加不确定性，不增加一个黑箱方向分

**已核验事实：**[时间序列 Bootstrap 文档](https://bashtage.github.io/arch/bootstrap/timeseries-bootstraps.html)提供 Stationary、Circular Block 和 Moving Block 方法；[`arch/bootstrap/base.py`](https://github.com/bashtage/arch/blob/main/arch/bootstrap/base.py)有对应实现、随机种子和区块长度参数。[许可原文](https://raw.githubusercontent.com/bashtage/arch/main/LICENSE.md)为 NCSA 类型宽松许可，不应随意改写成 MIT。

**合理推断：**对于按规则采样的收益或事件统计，可用保留局部序列相关的重采样对照简单独立样本方法，观察结论对区块长度和样本段是否敏感。但稀疏、聚集或重叠事件需要自己的抽样设计；套用 Bootstrap 不会自动消除混杂、选择偏差和多重试验。

运行在 Python 科学计算环境，不附带市场数据，无必要的常驻服务。[发布记录](https://github.com/bashtage/arch/releases)中 8.0.0 是兼容性更新，含 Python/NumPy/pandas 支持和文档修正，支持“**成熟工具仍在维护**”的判断；维护响应时间和贡献者集中度未统计。

**竞争替代：预声明的分组统计＋现有测试环境。** 样本过少或没有不确定性估计需求时，先展示样本量、分布和局限更诚实。不默认把 GARCH、所有检验和全套策略回测都接入网站。

### 5.8 ruptures：用于事后分段，不直接充当实时市场状态

**已核验事实：**[官方文档](https://centre-borelli.github.io/ruptures-docs/)和[作者综述](https://arxiv.org/abs/1801.00718)将其定位为离线变点检测；[`src/ruptures/detection/pelt.py`](https://github.com/deepcharles/ruptures/blob/master/src/ruptures/detection/pelt.py)给出具体算法；[许可](https://raw.githubusercontent.com/deepcharles/ruptures/master/LICENSE)为 BSD-2-Clause。

它可以帮助复盘“波动或相关结构在何时改变”，但将全样本分段标签回填历史，再宣称当时已经识别市场状态，会引入未来信息。

Python 及其科学计算依赖即可，无数据、无托管服务要求。[发布页](https://github.com/deepcharles/ruptures/releases)的 1.1.10 含 macOS ARM64 构建与文档维护；因此可判断**维护仍存在、更新范围有限**，不能仅据此断言停止维护，也不能保证所有算法适合金融序列。

**竞争替代：只用过去数据的滚动波动/趋势规则。** 后者解释成本低。需要在线状态时，应验证滚动拟合、检测延迟和追加未来样本后的历史标签变化；离线分段单独显示，不混入实时预警。

### 5.9 Lightweight Charts 与 KLineChart：选择交互收益，不选择截图

**Lightweight Charts。已核验事实：**[IChartApi](https://tradingview.github.io/lightweight-charts/docs/api/interfaces/IChartApi)提供图表交互接口；[Apache-2.0 许可](https://raw.githubusercontent.com/tradingview/lightweight-charts/master/LICENSE)之外，项目 [README/NOTICE](https://github.com/tradingview/lightweight-charts)有署名和链接要求。[发布记录](https://github.com/tradingview/lightweight-charts/releases)包含 pane、resize 和绘制问题修正，属于**活跃维护**，不是无缺陷。

它适合浏览器局部复用，不附带行情、数据授权或 TradingView 商业足迹功能。足迹自定义层的成本必须另验，不能把商业网站能力当作开源库能力。

**KLineChart。已核验事实：**有[中文官方文档](https://klinecharts.com/)和 [Apache-2.0 许可](https://raw.githubusercontent.com/klinecharts/KLineChart/main/LICENSE)；[10.0.3 发布记录](https://github.com/klinecharts/KLineChart/releases)包括覆盖物层级和历史加载修正，属于**活跃演进**。它是绘图/指标交互的竞争替代，但维护者集中度和现有 CSS/状态兼容性未知。

**取舍：**二者都只消费同一查询结果。先比较“定位异常、查看证据、保存标注、恢复历史窗口”的任务，不并行保留两套长期图表数据层。现有图表能完成任务时，两者都不必引入。

### 5.10 AI SDK：适配模型和工具，不替系统证明事实

**已核验事实：**[Apache-2.0 许可](https://raw.githubusercontent.com/vercel/ai/main/LICENSE)；官方文档源码 [`content/docs/03-ai-sdk-core/15-tools-and-tool-calling.mdx`](https://github.com/vercel/ai/blob/main/content/docs/03-ai-sdk-core/15-tools-and-tool-calling.mdx)描述工具输入 schema、执行结果、步骤记录和停止条件。[发布记录](https://github.com/vercel/ai/releases)说明它在持续演进。

复用对象是 JS/TS 模型与工具适配，不是新建自主研究组织。维护判断为**活跃演进，版本配对需回归**。现有云端执行计划可保留；实际 provider、运行时、流式响应和超时行为由仓库实验确认。

SDK 免费不意味着模型推理、网关、检索或数据权利免费。停止条件也不替代单次工具超时、总费用和权限控制。程序仍负责数值计算、cutoff、来源选择、证据 ID 和用途过滤。

**竞争替代：已有直接模型适配＋类型校验。** 它已经清楚且稳定时，不为获得 SDK 名称而迁移。Python 研究成为主要执行环境之前，也不另增第二套 Python 代理框架。

### 5.11 promptfoo 与 ALCE 方法：测试报告，而非再建一个报告代理

**已核验事实：**promptfoo 的[断言文档](https://www.promptfoo.dev/docs/configuration/expected-outputs/)包含确定性断言、自定义 JavaScript/Python 和模型评分；[MIT 许可](https://raw.githubusercontent.com/promptfoo/promptfoo/main/LICENSE)与[运行要求](https://github.com/promptfoo/promptfoo/blob/main/package.json)可核查。检索时主分支声明 Node ≥22.22.0；这只是拟选版本兼容性检查线索，不是升级现有系统的命令。[0.123.0 发布说明](https://github.com/promptfoo/promptfoo/releases)日期为 2026-09-10，包含工具调用断言和存储修复，属于**活跃演进**。

建议只作为本地或 CI 测试依赖，不增加常驻服务。模型调用、评分模型和托管功能分别计费；运行前需核查配置、网络出口、遥测和样本保存，不把“本地 CLI”理解成默认不联网。自定义断言本身可执行代码，不能直接运行不可信配置。

[ALCE 论文](https://aclanthology.org/2023.emnlp-main.398/)提供引用质量评估方向，可借鉴“引用是否真正支持主张、重要主张是否得到覆盖”，但其通用问答基准不是 BTC 报告通过标准；本版只借鉴方法，不复制未核许可的数据集。

**竞争替代：现有测试框架＋固定样本和人工盲评。** 只有多模型/多提示词回归管理已形成重复劳动时才引入 promptfoo。模型裁判可辅助语言评价，不能替代确定性数值检查或授权判断。

## 6. 面向比特币分析的五项能力组合

### 6.0 共同前提：统一的是契约，不强求统一所有来源

以下是建议的数据契约，不声称本仓库已经缺少这些字段，也不要求直接采用这些名称。

| 契约 | 应保留的最小语义 | 关键区别 |
|---|---|---|
| Instrument | 来源、市场类型、原始代码、基础/报价/结算币、乘数、价格/数量精度、到期、生效区间 | 同名 BTC 合约不等于同一产品；规格会变化 |
| Event | 来源事件时间、接收时间、原始 ID/序列、频道和 payload、单位、适配版本 | 事件发生、系统收到、后来入库是三个时间 |
| Observation | 观察期间、发布/可见时间及精度、首次获取时间、修订版本 | 观察月份不是发布日期；日期级 vintage 不是精确到秒的发布记录 |
| Dataset | 来源/范围、文件哈希、摄取时间、版本、已知缺口、质量与权利 | 哈希一致不证明覆盖完整；来源修订产生新版本 |
| Metric | 输入版本、窗口、方法与参数版本、单位、来源覆盖、完成状态 | 同名指标可能算法、样本和价格桶不同 |
| Evidence/Report | cutoff、事实 ID、证据定位、方法、局限、模型/模板配置、允许用途 | 当时报告与用新数据重算的报告不是同一对象 |

建议采用 UTC 作为内部对齐基准，但保留原始时区、精度和单位；数值/ID 超过 JS 安全整数范围时采用适当表示。窗口统一约定为左闭右开，来源的 K 线开盘时间、统计期末和资金费结算点要分别映射，不能统一改名为 `timestamp` 后忽略语义。

还应区分两种历史问题：**“公众当时已经能够知道什么”**和**“本系统当时实际知道什么”**。前者依赖可信发布时间，后者依赖系统首次观测日志；不能只用一个 `available_at` 字段掩盖两者差异。

### 6.1 能力 A：版本化证据链与可回放指标

**用户问题与价值。** 如果某个历史数值重新打开后变化，或页面、导出与报告数字不同，使用者需要知道这是数据修订、方法改变、缺口补齐还是实现错误。能力 A 的价值是可解释这些差异，不预设当前系统存在此类错误。

**最小方案与复用方式。** 选一个已经使用的 BTC 来源、一项现有指标和一份报告；保留获准保存的输入版本、方法参数和结果清单。优先局部扩展现有存储/API。原始批次较大、SQL 扫描成为问题时，才以文件方式试 Parquet/DuckDB，不先迁库。

**数据链路：**现有来源或授权归档 → 原文与摄取版本 → 标准化/缺口检查 → 当前数据库或分区文件 → 单一权威指标计算 → 统一查询 API → 页面、导出、报告证据。

**关联检查。** 开发者需检查前端共享选择状态、缓存键、浏览器本地计算、导出重新查询、LLM 输入和历史报告读取是否使用同一窗口/版本。缓存身份至少应能区分数据版本、方法版本、参数与截止点；实际字段设计由仓库决定。

**代价与责任。** 主要是增加历史版本与质量元数据的存储、保留策略、修订识别和重算责任。不能为“留存全部数据”违反来源条款；不允许保存的原文改为获准的证据定位和派生结果，并明确无法完全重放的范围。

**验收。** 相同输入版本和参数可重算；注入重复不会改变应去重总量；可识别断档不被标成完整；追加未来数据不改变冻结报告；修订后产生可解释的新版本。对无连续序列的来源，不声称能证明所有隐形缺口。

**不采用条件。** 已有机制完整时只补文档或测试；没有原始历史则缩小到已有聚合或未来采集，不能用 K 线补造“真实逐笔”。没有历史重现需求时，也不必永久保留每个高频事件。

### 6.2 能力 B：口径明确的订单流与衍生品工作区

**用户问题与价值。** 如果系统只能显示“涨跌＋指标”，可能难以区分价格变化伴随的是主动成交、持仓变化、清算事件还是期权报价变化。新增能力应提供可核验的市场条件，不是未经验证的多空评分。

**最小方案。** 从一个现货/永续组合开始，采用实际可取得的成交、资金费、OI 和价格基准；期权仅增加有限期限快照。没有研究任务要求，就不采完整 L2、所有交易所和全部期权更新。

**复用与链路：**原生接口或通过实验的 CCXT → 来源特定语义映射 → 版本化批次/聚合 → CVD、资金费对照、基差、OI 变化、期权截面 → 统一 API → 联动图和证据摘要。Deribit 先接 API 快照；vollib 只作为独立计算对照；Tardis 仅补明确缺失的获授权历史。

**必须分开的五类量：**

| 展示内容 | 最少的解释与检查 |
|---|---|
| 真实主动成交足迹/CVD | 主动方向来源、成交粒度、累计起点、桶宽、币量/名义量、交易所覆盖和缺口 |
| 估算足迹/方向量 | 明示价格方向分类或其他估计方法；历史粒度变化和重绘单独记录，不与真实主动量无标记拼接 |
| 可见订单簿热力图 | 快照/增量序列、可见深度、恢复状态；盘口减少不自动等于成交 |
| 观测清算事件 | 来源采样、方向含义、数量字段、价格类型；重复/累计快照不能直接相加 |
| 清算位置估计热力图 | 模型/供应商、版本、输入和不确定性；不能称为全市场真实仓位分布 |

估算足迹与清算模型的差别分别由 [TradingView 方法](https://cn.tradingview.com/support/solutions/43000726164/)和 [CoinGlass API 描述](https://docs.coinglass.com/reference/liquidation-aggregate-heatmap)支持；二者都不能替代真实事件记录。

资金费需保留预测/已结算、结算时间和覆盖间隔；基差需说明现货基准、币种换算和期限；OI 是存量，价格变动、规格与单位影响名义值，不能把其变化直接称作净资金流。跨所统计先逐源展示，再定义有范围的合成指标，而不是宣称“全市场”。

**关联检查。** 图表缩放、周期切换、导出和 LLM 必须携带同样的分类方法、来源集合与质量标记；历史页面不能把新补齐数据悄悄替换当时预警证据。共享 price/side/quantity 类型需要检查是否容纳来源差异。

**代价与验收。** 成本主要来自持续采集、丢包恢复、历史购买、单位回归和存储。验收依赖固定样本对照、异常降级、口径守恒及当前/历史一致性；不以“图画出来”或“能连接 WebSocket”为通过。无可靠成交方向可降级估计，但须独立命名；没有数据授权或实际研究价值则停做对应来源。

### 6.3 能力 C：时点正确的事件与跨资产研究

**用户问题与价值。** 如果使用者想判断“某类宏观或 ETF 事件发生时 BTC 通常如何变化”，系统需要避免拿最终修订值解释当时未知的信息，并应显示样本量和不确定性。目标是从叙述走向可重复研究，不默认提供因果结论。

**最小方案与链路。** 先声明一个研究问题、事件定义、比较窗口和基线，再选一个有可靠发布时间/版本的来源：原始发布/FRED vintage → 时点观察表 → 与 BTC 数据做 as-of 对齐 → 固定规则事件统计 → API → 事件时间线、结果分布和证据报告。必要时用 arch 估计不确定性；ruptures 仅作独立的事后结构分段。

其他来源作为扩展池，而非同时必做：

| 数据方向 | 可核验事实与原始入口 | 最小用途及不确定性 |
|---|---|---|
| 宏观、利率、美元与跨资产 | [FRED/ALFRED](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)提供版本机制；各序列权利与频率单独查 | 区分观察期、发布日期、修订；股票休市时沿用旧值不能算作新观测 |
| ETF | [IBIT 发行人页面](https://www.ishares.com/us/products/333011/ishares-bitcoin-trust-etf)提供带日期的份额等披露；[Farside](https://farside.co.uk/btc/)是另一个汇总来源 | AUM 变化不等于净申购；估计流量、发行人披露和汇总值分别保存；未到齐不填零 |
| 原始链上 | [Bitcoin Core getblockstats](https://bitcoincore.org/en/doc/30.0.0/rpc/blockchain/getblockstats/)提供区块统计、blockhash 等；裁剪节点部分历史不可用 | 区块 hash/height、重组和确认状态需要保留；节点本身不提供交易所地址归属 |
| 实体标签和矿工/交易所流量 | [Glassnode PiT](https://docs.glassnode.com/data/point-in-time-metrics)说明标签聚类与修正会改变历史，并提供 `computed_at` 的覆盖说明 | 标注“估计”；标签版本、计算时间和早期缺少字段的范围不能忽略 |
| 社区链上数据 | [Coin Metrics Community](https://docs.coinmetrics.io/packages/coin-metrics-community-data)采用 CC BY-NC 4.0 | 适合符合授权的研究探索；商业展示前另取得权利 |
| 稳定币 | [Circle](https://www.circle.com/transparency)披露周度储备及相关 mint/burn 信息；[Tether](https://tether.to/en/transparency/)说明流通数据通常日更 | 属发行人披露，不是本系统独立审计；需区分原生供应、桥接表示、授权未流通与实际流通 |

这些来源的发布机制可核验，但完整历史、自动化下载权、商业 API 费用、实际延迟和再分发权没有全部核清。公开披露的存在，不是“免费完整数据管道已经可用”。

已知系统涉及 Yahoo，不等于已知使用 yfinance。后续需核对实际适配方式、复权规则、交易日历和数据用途；[yfinance 官方项目](https://github.com/ranaroussi/yfinance)明确说明它不是 Yahoo 官方服务，并提示个人研究使用及数据权利限制。本轮没有完成 Yahoo 全部适用条款审查，不建议仅因存在开源封装就把它升级为生产唯一来源。

**研究验证最低标准。** 事件定义和窗口在看结果前固定；保存尝试过的参数和候选集合；训练/验证按时间分离；只在训练期拟合阈值、标准化与状态模型；对重叠事件与收益窗口进行隔离或按簇处理。描述历史收益分布与模拟可交易收益分开，后者才加入执行时点、手续费、点差、滑点和资金费用。

因果结论需要额外识别设计；同期上涨不证明 ETF 流入或某条新闻导致上涨。市场状态工具必须区分只使用过去数据的在线判定与利用全样本的离线分段，不能混写。

**关联检查。** 查事件时间线、新闻转载去重、宏观缓存、ETF 空值、跨资产交易日历、导出中的 vintage 和 LLM 截止点。新闻/社媒先做来源与事件索引，不为“舆情全覆盖”引入未经授权抓取或把转载量当真实关注度。

**代价、验收、退出。** 成本是历史版本、来源授权、对齐规则和实验记录，不一定是新服务器。验收看截断后数据不进入过去、同一研究可重现、修订影响可解释、样本外结论不被事后改规则。历史版本不足时只保留当下描述；样本太少时报告不确定性，不输出精确成功概率。

### 6.4 能力 D：证据约束的 LLM 报告和回归评估

**用户问题与价值。** 如果报告能写通顺文字，却不能说明数字来自哪个窗口或为何改变，模型输出就难以成为研究材料。新增能力是可检查和可比较，而不是提高文字长度。

**最小方案与复用。** 保留已有云端任务；给它增加冻结证据包、模板基线、程序校验和报告版本。现有模型适配足够时不换 SDK；重复适配明显时使用 AI SDK；回归样本管理困难时使用 promptfoo 的本地/CI 形式。

**数据链路：**统一数据/指标 API → 冻结 cutoff 与证据包 → 数据用途过滤 → 模型只读工具或直接证据输入 → 结构/数字/来源校验 → 带版本报告 → 历史页与评估记录。

建议输出明确区分：**事实、解释、待验证假设、反证、数据局限**。关键数字由程序填入或引用 evidence_id；引用必须支持对应主张，而不只是链接存在。模型可以提出其他解释，不能擅自换窗口、补缺失数值或将预测写成观测。

**关联检查。** 检查云任务的重试、并发、缓存、恢复、模型配置、报告覆盖写入、导出、工具权限和来源内容隔离。外部文章是数据，不允许改变系统权限；工具只读、来源白名单、单次超时、总调用/费用上限与秘密隔离是建议边界。新 SDK 的默认循环行为不能代替项目自己的预算。

**数据权利。** 先判断原文、派生数据和外部模型用途是否获准，再形成 payload；内部 `allowed_uses` 标签只是执行已经确认的政策，不会自行产生授权。受限数据可以仅留在允许的确定性展示路径，但具体衍生分发权仍需核验。

**代价与验收。** 成本是模型调用、测试维护、审阅和证据存档。比较同一证据下模板与 LLM 的正确性、解释增量、遗漏、成本和延迟；程序核数字，人工抽查论证，模型裁判只辅助。关键事实不受支持时拒绝发布或降级，不让重试无限进行。

**不采用条件。** LLM 比模板更昂贵却没有解释增量，或授权不允许外部推理时，保留模板。多加代理不能解决上游事实错误；本轮不推荐多代理。

### 6.5 能力 E：联动研究工作区与可解释预警

**用户问题与价值。** 如果使用者需要反复在图表、新闻、指标和旧报告间重新定位日期，或预警出现后无法复原依据，研究效率会下降。新增价值是减少定位与重复劳动，不是更多可拖动面板。

**最小方案。** 保留现有图表，新增共享 instrument/窗口/数据版本、事件点击定位、证据侧栏、带假设与失效条件的笔记，以及站内预警记录。只有现有图表确实限制任务才比较 Lightweight Charts 与 KLineChart；暂不需要新的通知服务。

**数据链路：**统一指标和质量结果 → 确定性规则判定 → 预警状态/证据快照 → 现有 API → 站内记录、图表定位、笔记与报告关联。

建议将预警定义为带状态的事件，而不是每次轮询满足条件就发一条：区分首次越过、持续满足、恢复和冷却；阈值附近抖动可以使用明确的滞回规则。数据过期、缺口或估计方法变化时，应抑制、降级或单独报警，不能继续发正常行情信号。

**关联检查。** 前端全局状态、跨面板时间同步、标注持久化、缓存版本、导出、报告反向链接，以及历史预警是否被新数据重算覆盖。研究笔记保存的是某次假设及当时证据，不只是屏幕坐标。

**代价与验收。** 代价集中在状态模型、前端回归、标注兼容和预警规则维护；外发通知会新增账号、费用和权限，应另立决策。固定任务对照应显示操作更少或错误更少；重复调度不重复触发；断线恢复不漏记状态转移；历史入口能恢复当时窗口与证据。

**不采用条件。** 实际研究任务很简单、现有交互已足够，或新工作区增加操作成本时，保留局部证据入口，不迁移整站。

## 7. 三种架构路线及条件化推荐

### 7.1 路线对照

| 维度 | 路线 A：现有架构局部演进 | 路线 B：新增专用数据/计算服务 | 路线 C：较大架构调整 |
|---|---|---|---|
| 适合的任务/规模 | 聚合数据、宏观、有限快照和定时报告；实际表大小、查询与 CPU 在平台边界内 | 必须持续采集，或代表性历史研究超出现有任务模型；有明确运维责任人 | 多任务/多用户持续竞争资源，系统主体已转为数据后端，局部边界导致可测重复成本 |
| 能力支持 | A/C/D/E 通常可先局部增强；B 可从低频衍生品快照开始 | 连续成交/盘口、历史回放、Python 数值分析、较重批处理 | 统一后端、持续在线分析和更复杂资源管理 |
| 具体限制 | 原生依赖、长连接生命周期、单库与查询边界；不宜未经测量逐事件写 D1 | 新增部署、网络、备份、版本和跨服务契约 | 迁移范围大、回滚复杂，容易与仓库治理重叠 |
| 新增部署单元 | 可以为零；对象存储、任务机制按需 | 最少一个批处理任务或一个长期采集服务；两者不必同时出现 | 后端/任务/数据库等，仍可模块化单体，不默认微服务 |
| 渐进边界 | 一条指标链、一个报告、一个页面 | 一种来源或一个计算任务输出稳定文件/API | 逐能力替换，双路对照后切换，不全仓一次重写 |
| 支持选择的证据 | 当前实现可复用，局部补充达到验收 | A 经合理优化仍无法满足明确任务，且 B 实验收益足够 | B 的跨边界重复复杂度已实测高于集中调整成本 |
| 推翻选择的证据 | 真实任务反复碰到硬限制或可靠性边界 | 新服务没有净收益、维护无人负责、数据不获准 | 核心问题只在少数模块，A/B 已能解决 |

**有前提的首选：路线 A。** 先在现有职责边界内补能力和验证。若仓库及实验共同证明持续流或计算需要独立环境，再局部走 B。仅有“项目老”“原生 JS”“想用 Python”都不足以选择 C。

推荐的 B 也不固定为“Cloudflare＋常驻 Python＋DuckDB 服务”：一次日度研究可能只需按任务启动的计算进程；只有持续流采集才需要持续运行。已有独立环境存在时优先复用，避免重复建设。

### 7.2 Cloudflare 当前限制：硬限制、配置与估算分开

| 项目 | 已核验的官方事实 | 应如何用于决策 |
|---|---|---|
| D1 大小 | 免费单库 500 MB、付费单库 10 GB；付费单库上限不可提高 | **产品硬限制**，不是对整个项目总数据量的自动判决 |
| D1 查询 | 最大 SQL 执行 30 秒，批调用也受相应总时限；各实例单线程 | **执行边界**；先看查询计划、读写路径和复制方式 |
| D1 读副本 | 可扩展读路径；Sessions/bookmark 处理副本一致性 | **可选能力**；不等于增加单库容量或解决写入瓶颈 |
| Workers CPU | 付费计划默认 30 秒 CPU，可配置到 300 秒 | **默认配置与最大额度不同**；CPU 时间不是网络等待或所有触发类型的统一墙钟时间 |
| Durable Objects 出站 WebSocket | 出站连接不能使用服务器侧 WebSocket 休眠模式 | **生命周期与费用条件**；不能套用浏览器连接的休眠成本模型 |
| Workers / R2 价格 | Workers 付费基础订阅 5 美元/月；R2 Standard 0.015 美元/GB·月，A/B 操作分别 4.50/0.36 美元每百万次，另有计费规则与免费额度 | **官方单价，不是系统报价**；还要算操作、计算、数据、模型和维护 |

来源：[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)、[D1 读副本](https://developers.cloudflare.com/d1/best-practices/read-replication/)、[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)、[DO WebSocket](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)、[Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)、[R2 定价](https://developers.cloudflare.com/r2/pricing/)。以上均于 2026-09-16 查询。

**合理推断：**读副本的 Sessions/bookmark 处理相应读一致性，并不等于冻结历史研究快照；bookmark 表示至少达到某个数据库版本，而不是固定在该版本。报告跨多个查询、来源和采集时间时，仍需应用提供冻结证据边界。

本报告没有真实账单或事件率，因而不给出月总费用。后续估算应基于“实测事件率×编码后大小×保留时间”，分别加入原始、标准化、派生层和必要副本；请求次数、小文件数量和扫描量单列。不要套用未经测量的压缩比。

### 7.3 不为“生产级”堆叠组件

当前定时器和任务账本能实现恢复，就不额外上编排平台；需要持久分步恢复时再评估 [Workflows](https://developers.cloudflare.com/workflows/reference/limits/)。需要缓冲生产与消费时再考虑 Queues，其[至少一次交付](https://developers.cloudflare.com/queues/reference/delivery-guarantees/)意味着应用仍须幂等，不能把重复报告或重复成交交给队列自动解决。

最低可观测性围绕来源最后成功时间、已知缺口、修订、任务失败与报告拒绝原因建立；服务器“在线”不是数据新鲜度。备份验收以能重建一个数据分区或报告为准，不以配置文件里出现备份任务为准。

## 8. 优先讨论的五项升级及取舍

这里的优先级是**讨论和验证顺序**，不是执行授权。

| 能力 | BTC 分析价值 | 数据可得性/可信度 | 兼容性与维护代价 | 证据强度与依赖 | 讨论顺序 |
|---|---|---|---|---|---|
| A 版本化证据链 | 跨所有分析，主要减少不可解释错误 | 可从已有数据做起；历史完整度未知 | 最可能局部接入；增加版本/保留责任 | 外部事实强；仓库缺口未知；依赖最少 | **先核查已有能力，再补缺** |
| D 报告与回归评估 | 直接影响现有云端报告可信度 | 依赖现有获准证据，避免先买数据 | 可保留模型接入；维护评估样本 | 方法证据强，模型增量须实验；依赖 A 的最小快照 | **与 A 配套讨论** |
| C 时点事件研究 | 增加可重复的分析深度 | 宏观版本较明确，ETF/标签历史不齐 | 中等数据治理成本；可批处理 | 时点方法强，特定研究结论未验证；依赖 A | **先做一个研究问题** |
| E 联动与预警 | 减少研究操作和证据查找 | 不必新增外部数据 | 局部前端改动优先；收益取决于真实任务 | 接口能力有证据，用户效率未知；依赖 A/指标质量 | **先原型对照，不先换图表** |
| B 订单流/衍生品 | 对短时市场条件有价值 | 高频完整性、合约口径、授权更复杂 | 持续采集和历史成本可能最高 | 协议差异证据强，预测增量无证据；依赖 A | **先有限样本试验，再扩范围** |

如果真实使用需求以订单流为核心，B 可以提前，但仍须先完成对应 A 的最小数据链；如果主要消费宏观报告，C/D 更值得优先。不能以“金融平台通常都有某功能”代替使用需求。

**推荐采用：**版本/时间/质量/证据机制、最小回归验证、局部联动。
**值得试验：**有限衍生品快照、必要的 CCXT/DuckDB/vollib/arch/promptfoo，以及有实际交互收益的图表替代。
**仅借鉴思想：**PiT、离线分段、商业工作区与引用评估方法。
**暂不采用：**无触发条件的数据库迁移、整个平台替换、多代理及交易执行扩张。

## 9. 五个最小验证实验

**以下均未在本轮执行。** 输入优先使用现有、可合法处理的只读副本或明确标注的合成样本。涉及安装、实际网络采集、模型调用、费用或生产副本提取，须在后续实施阶段单独确认。

| 实验 | 输入与步骤 | 可观察结果与成功标准 | 停止条件与缩小方式 |
|---|---|---|---|
| E1：同一指标能否重放 | 一个来源、一段固定原文/聚合、当前算法；注入重复、可识别缺序列、时间单位错误和上游修订；比较页面/导出/报告路径 | 固定输入可复算；精度容差预先声明；可识别异常被标记；冻结版本不被新输入改变；来源覆盖未知时不标完整 | 原始数据不足则只验证已有粒度；不补造逐笔。仅当当前查询确实不达标，才在隔离环境比较 D1 原路径与 DuckDB 文件路径 |
| E2：衍生品语义与期权对照 | 来源官方字段样本、有限实际快照或合成边界样本；覆盖 maker/taker、被清算方向、破产价、期末 OI、空报价、不同结算币；必要时 IV 价格往返 | 单位/方向与原协议一致；不同价格类型不混算；无报价不造 IV；来源 IV 与自算差异能归因到约定或数据 | 无法解释差异，先禁用合成分数和全市场总量；只保留带来源的原始截面；不扩交易所 |
| E3：时点与事件研究 | 一个有修订的宏观序列、事件清单、BTC 窗口、ETF 未到齐合成样本；分别按最终值和当时版本计算；追加未来数据做对照 | 截止后信息不进入过去；未知不填零；事件定义/窗口不随结果更改；固定研究可重现；统计假设与样本量可见 | 无可信发布时间则降为日级或当前描述；样本不足不估精确概率；没有稳健增量就停止复杂模型 |
| E4：LLM 与模板对照 | 相同获准证据包；正常、缺失、冲突、过期、单位错误、假引用和外部恶意指令样本；比较模板和模型输出 | 关键数值/引用检查通过；受限字段未外发；缺失不被编造；人工确认解释增量；费用与延迟在事先约定范围 | 不支持的关键事实存在即拒绝发布；程序填数、缩小任务或回退模板；不以多代理补救 |
| E5：研究现场与预警恢复 | 同一数据窗口、当前页面和局部原型；执行定位异常、追证、保存笔记、返回旧报告；注入重复调度、阈值抖动、过期和重启 | 相同事实显示一致；任务更少错误或更少操作；预警状态转移可解释且不重复；历史快照可恢复 | 没有交互净收益则保留旧图表；暂不外发通知；只保留证据入口和站内记录 |

性能实验需要先确定真实任务的新鲜度、延迟和预算目标，采样包含典型负载与波动高峰；分别记录冷/热缓存、失败、扫描、内存与恢复。本文没有预设一个适用于所有系统的毫秒阈值或“提升百分比”。

研究验证还应区分：**冻结输入下结果稳定**与**使用更新版本后允许结果变化**。追加未来数据不应改变因果可用的过去结果，但主动选用新 vintage 重算产生差异是合理的，必须显示新版本，而不是禁止所有修订。

### 10.2 能力 A 的仓库对照卡

**已经确认的外部事实：**Binance 归档可以后续替换；来源时间、聚合和单位存在差异；D1 限制需要结合读副本和真实查询路径理解。直接依据见第 2、5.1、7.2 节。

**尚未确认的本仓库假设：**是否保留输入版本；同一指标是否有多份实现；原始历史与导出/报告是否共享截止点。不得把任一项预设为缺陷。

**应查职责与配置：**来源接入与回补、数值/时间转换、数据库读写、指标计算、缓存、浏览器状态、导出生成、报告历史、对象保留策略和测试样本。

### 10.3 能力 B 的仓库对照卡

**最小实验与退出：**E2，观察固定样本的方向、单位、价格类型与期权质量，不以连接成功为验收。若数据不足，只保留来源限定的截面或明确估算，不输出合成全市场结论，也不增加采集范围。

### 10.4 能力 C 的仓库对照卡

**已经确认的外部事实：**ALFRED 有日期级历史版本机制；部分链上实体指标可能因标签变化修订；发行人披露、ETF 汇总和稳定币供应不是同一类资金流观测。

**接入前必须回答：**这是当前描述还是历史可用性研究？哪些来源有可信发布时间？有没有完整历史事件定义？是否保留失败实验与参数尝试？跨资产价格和基准授权是否允许目标用途？

### 10.5 能力 D 的仓库对照卡

**已经确认的外部事实：**AI SDK 有工具 schema/步骤机制；promptfoo 可组织确定性和模型断言；引用链接存在不等于主张受支持；数据权利可以限制外部服务商和衍生输出。

### 10.7 开发代理应提交的讨论结果

建议只读核验阶段产出一份对照记录：每项能力标记“已有且成立、已有但待实验、确有缺口、不适用、证据不足”，附实际代码位置和数据流证据；只为确有缺口的部分提出最小变更。

每项拟议变更还应说明共享状态、缓存、导出、LLM 输入、历史展示的影响，列出回退边界、实验输入、停止条件与后续费用/授权问题。若涉及结构整理，应先与现有仓库治理工作划分责任，不借能力升级重新安排大规模治理。

**这份材料授权的是讨论依据，不是“让 Codex 自动执行所有候选”。** 对外联网采集、安装运行、付费、账号和生产数据操作不在本轮范围内。

## 11. 暂不采用的方案及重新考虑条件

| 方案/方向 | 当前不采用理由 | 重新考虑触发 |
|---|---|---|
| 全量迁库、Kafka/Kubernetes、默认微服务 | 没有实际吞吐、并发和运维证据；增加故障域，与治理可能重叠 | 可重复瓶颈、团队责任和净收益实验同时成立 |
| 多套采集器、图表、DataFrame 或代理框架并行 | 同一职责重复，语义和版本漂移可能超过节省的代码量 | 不可替代能力明确，且有清楚边界与维护负责人 |
| 直接整体搬入 OpenBB 等完整平台 | 先前平台发现有参考价值，但本轮没有证明它比现有适配/API 更合适 | 某个 provider 或研究流程显著减少持续维护，再独立核验该组件 |
| 将 vectorbt 当纯 Apache 组件直接商业化 | [当前许可](https://raw.githubusercontent.com/polakowo/vectorbt/master/LICENSE.md)附 Commons Clause；不应一概认定所有商业内部使用禁止，也不能忽略限制 | 明确具体用途并核权利；复杂实验确实优于简单研究脚本时再比较 |
| 完整交易执行、账户/资金管理平台 | 不属于分析系统本轮目标 | 用户另行定义交易项目、权限和风险边界 |
| 多代理研究组织 | 事实、时间和证据问题不靠角色数量解决 | 单工作流存在已证明的分支/恢复问题，且对照实验有净收益 |
| 全市场历史 L2、全节点和自建链上标签体系 | 数据量、授权和运维高；不一定增加当前研究价值 | 有不可替代的问题、合法历史/样本和持续维护资源 |
| 将清算热力图、实体流量、估算足迹作为直接事实 | 混淆观测与模型，结论不可核验 | 仅进入明确估计层，保留方法、版本和不确定性 |
| GPU 期权计算、新论文方法直接上线 | 没有计算瓶颈与稳定性证据，数值模型约定尚需先验 | 现有正确实现出现实测瓶颈，数值与性能对照通过 |
| 未经授权的社媒全文库、免费接口拼成商业数据库 | 公开访问、代码开源和可商业再分发不是同一权利 | 取得对应许可、保留/删除政策和成本边界 |

vectorbt 的限制来自许可原文，不应扩大解释为禁止所有企业研究；同样，AGPL 或付费服务也不是自动淘汰理由，真正的问题是与预定用途、维护成本和交付方式是否匹配。

### 12.2 未解决问题与可信度边界

**无需查看仓库也成立：**必须区分来源语义、修订与观测时间；估计不等于观测；代码许可不等于数据/模型/分发许可；图表和代理框架不会自行证明分析正确。这些原则有本轮直接反例支撑。

**查看代码后才能决定：**现有能力是否已经满足要求，权威指标计算位置、状态和缓存改法、是否需要新依赖、是否能局部接入以及与治理的边界。本文没有对这些未知项作诊断。

**必须实验才能决定：**真实数据完整率、来源覆盖、适配器正确性、查询延迟、冷启动、资源成本、图表效率、模型增量、统计结果稳定性，以及 A/B/C 架构哪条实际更好。

**仍需外部确认：**具体商业用途的数据许可、衍生报告和云端推理权、供应商报价、部署地区合规可达性、服务承诺和长期维护人。没有找到限制不能写成没有限制；没有测试失败不能写成已经稳定。

本轮没有生成全部网页的独立档案，没有完整审计候选的依赖树、漏洞、贡献者集中度或所有测试。正式引入前应针对拟用版本保存许可证、相关方法页/条款和可允许保留的证据；默认分支、无年份的发布摘要及当前网页不能单独证明历史状态。
