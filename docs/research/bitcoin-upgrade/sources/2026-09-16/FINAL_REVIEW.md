# 当前总纲｜围绕研究任务，而不是围绕文件数量执行

版本：final-review-1.1-design。当前设计已经整合终审更正；旧包仅在90_archive留档。详细状态见[终审](02_adversarial_review/01_adversarial_review.md)。

## 1. 不变的产品目标

用户需要看懂发生了什么、什么真正改变、证据是否支持、哪里还不知道，并回头检查过去观点。数据展示、信息收集和分析是职责，不必须对应三个部署服务。价格等结构化观察和事件材料并行进入研究；解释由程序事实与可核对证据约束。

已有数据、足迹、强平、快照和云报告不是待从零补齐。当前需要纠正固定分数的概率外观、缺失伪中性、输入捕获不统一、来源身份和历史恢复边界；这些定位来自事实报告，不表示每份既有报告都有错误。

## 2. 五个“最少做到”，而不是五个新平台

|能力|最小有用产物|不必先建设|
|---|---|---|
|事实与变化|选定市场/窗口的同口径事实及比较；初始时明确基线|全量指标重构、每个family统一迁库|
|独立材料|填一个信息缺口、保留来源/版本/更正/失败|全网RSS、向量集群、通用爬虫平台|
|解释与条件|一个可核对简报，允许无变化或不足|五角色轮流总结、概率评分器|
|证据与历史|本次实际输入/结果身份、证据入口及诚实恢复等级|30个新物理表、完整原始逐笔档案|
|价值验证|对照旧版、合理模板与增强版，记录错误/遗漏/时间/费用|预先承诺准确率或提升百分比|

数据质量做到与启用能力相称：用了强平金额就核价格类型和数量语义，没用强平就不为首份价格简报改整个强平系统。安全和来源用途不能因快速交付省略；它们也不应扩张成完整企业IAM或法律自动化平台。

## 3. 当前首选架构

保留已证明可复用的现有JS、Pages/Workers/D1和模型适配；建立一个明确的研究输入责任边界。它可以仍在现有模块内实现，不强制抽出服务。长历史批计算和持续采集分别由真实任务判断：需要Python数值库可以是按次批处理，不等于24小时常驻；需要长期连接才验证相应生命周期。

三条路线都保留：局部演进适合当前有限输入；混合服务适合已测出的生命周期/计算需求；较大调整需要前两者的实际限制和运维资源。用户“允许大改”不等于“已批准迁移”，本方案也不以保守本身为目标。

## 4. 首次选择五种profile之一

- `market_template`：现有市场数据→确定性简报→证据和历史。没有模型调用，不要求模型预算设施。
- `collection_pilot`：一类实际需要的新材料→版本与更正→可检索证据。只向已有研究层输出，不复制第二事实池。
- `integrated_template`：把前两者接起来，检验新材料是否改变解释范围，而不是只增加文章数。
- `model_brief`：在已有市场模板上增加一次受约束综合与校验，不要求接入新来源。
- `integrated_model`：在已经连接有限事件的模板上增加模型。两种模型profile的预算、用途和外部调用范围必须明确。

各profile的任务、依赖和验收由[当前任务清单](10_final_review/scoped_work_packages.md)及机器清单定义。并行是允许，不是硬前置；既有来源足够就不要为凑两个来源增加采集。

## 5. 当前契约与旧设计的关系

原WP仍是完整能力的详细规格，部分范围不能标成整个WP已完成。F编号是本轮新建的scope任务，不篡改旧编号。当前research Schema为v2.1-design，collection为v2-design；旧对象只读适配，旧摘要和历史正文不就地重写。

运行模式request_bound/durable、生成模式template/model、结果状态initial_baseline/changes/nochange/insufficient分别处理。来源用途采用统一名称，时点模式统一publicly_available。新版本字段不能由模型填写成“已经验证”，服务端必须使用真实取得记录。

## 6. 开发前只需形成一页范围记录

明确问题、启用数据、输出、现有可复用点、涉及文件、采集和模型费用范围、验收与回退。现有实现已满足就复用；发现未知只阻断依赖它的能力。治理并发文件由同一集成人负责，不重开全仓整理。

第一次开发不保证任何研究收益；它交付可使用的产物和能够评价收益的证据。之后若简单模板已足够、来源没有独立增量或额外服务维护过重，停止扩张，保留退出理由。切片完成标准不是“所有候选已装”。

# 交付前终审｜从研究价值到可执行契约

版本：final-review-1.1-design；日期：2026-09-16。审查对象是上一轮188个文件的交付包、原16卷执行材料和用户事实报告；本次改的是文档及参考契约，没有修改业务仓库。

## 结论

方案的核心业务方向仍成立，但上一版还不适合让开发者不加区分地照表执行。问题不是“缺更多热门项目”，而是几个正例自检掩盖了契约反例，叠加多套当前规范与过粗任务依赖。此次直接修订当前文本/Schema/样例/入口，而非再附一层建议。旧包原字节在[历史档案](90_archive/README.md)。

第一性原理的审查标准是：一个输出能否帮助用户减少重要误读、识别新证据或恢复判断现场；若不能，它的指标、Agent、表、来源和文档数量都不构成价值。真实性、可用时点、适用范围、工作量和成本是约束；它们也不能被扩张为永远没有业务交付的理由。

# 契约迁移与适配说明｜v2.1 / collection v2

## 1. 范围

本轮只更改拟议契约与合成示例，未对真实数据表执行ALTER，也未推断线上字段。旧对象保留原内容、版本和摘要；需要使用新约束时经过明确适配，记录来源版本和无法提供的字段。不存在的历史数据不能由默认值补成“已验证”。

## 2. 新旧映射

|旧设计|当前设计|迁移规则|
|---|---|---|
|collection根type/object+$defs|oneOf+object_type|根入口实际应用具体类型；单类型校验仍需明确$ref|
|public_available|publicly_available|只在旧输入适配器转换并记日志，当前API拒绝旧拼写|
|internal_display/public_display/model_input|display_private/display_public/send_to_model|统一用途；不能只改字段名而扩大权限|
|example_only=true强制|record_origin|旧样例只能变synthetic；真实采集由服务端设observed；导入unknown不当现场证据|
|SourceCandidate active|SourceCandidate禁用＋SourceRegistration|新登记必须有真实端点、用途、网络/限制与owner，不复制整套法律自动化服务|
|first_seen/fetched|增加version_observed_at|URL首次见与此正文版本首次见分开；旧记录未知保持null|
|include_retracted=false|retraction_view|当前判断过滤撤回；私有历史视图可选当时版本，另附当前更正，今天权限始终生效|
|observed_sources|usable_sources|不是把收到HTTP200的源直接改名；必须满足该窗口的数据/解析/新鲜度规则|
|quiet=true单独布尔|coverage/comparison/domain约束|布尔是计算结果不是客户端或模型自授资格|
|RunRequest必填预算无生成模式|generation_mode/capture_kind/knowledge_cutoff|template预算可空；model须预算；历史截止独立于市场时间|
|无编码身份的bundle摘要|canonicalization_version|旧摘要保留legacy，不重新哈希后冒称同一历史输入|
|Report缺基线/覆盖状态|initial_baseline/insufficient_coverage|流程published与结论状态不同；nochange必须有有效覆盖和比较引用|

## 3. 三种历史读取

`system_observed`：本系统当时实际见到的那个版本；看version_observed_at，不以旧URL或旧发布日期回填新正文。

`publicly_available`：依据可信原始发布时间及当时版本重建公众可得信息；现在抓到的更正版不能自动代替当时版。无法证明则降为retrospective_latest或拒绝精确历史承诺。

`retrospective_latest`：明确事后整理。历史审计的当前更正提示与“截至当时证据”分栏，前者不能进入过去的预测输入。真实数据可能已删除或受限，返回恢复等级，不用新文章伪造恢复。

## 4. 资料撤回与权限不是同一维度

retracted表示来源撤回或主张失效，restricted表示用途禁止。获准私有审计可读取已撤回材料，以研究错误为何发生；没有当前使用权仍不得读取正文。普通模型输入默认不启用audit_history；未来若确有复盘模型任务，须增加独立用途与测试，而不是用现有布尔绕过。

## 5. 哈希与内容版本

Artifact摘要针对实际保存字节；本包sample_metrics.canonical.json与其locator、长度、哈希一致。漂亮排版的sample_metrics.json是阅读副本，不再被假称同一字节对象。

Bundle的受限profile `btc-ascii-key-json-v1`只允许非空可打印ASCII键、Unicode值原样、安全整数、布尔/null/数组、金融小数字符串；不含浮点JSON数，不改变数组顺序。它不是全量JCS。完整RFC8785还规定UTF-16属性顺序及数值序列化，不能由普通排序替代。[RFC8785](https://www.rfc-editor.org/rfc/rfc8785.html)

源正文A→B→A时内容A可共享字节对象，但第二次观察到A的事件不能丢失。抽取器升级只新增提取版本，不伪造来源更新。当前参考Article表将内容摘要唯一约束改成version_observation_key唯一约束，允许A→B→A生成新的观察版本，同时底层Artifact仍可去重。重复请求必须复用同一观察key或记unchanged；不能每次轮询都生成一篇新文章。真实仓库可用已有采集日志/版本头等价承载，不要求直接照搬新增列。

## 6. Schema和域校验的分工

Schema处理类型、必需字段、枚举、简单条件；FormatChecker验证日期格式。集合包含、跨引用owner、版本时间、当前政策、窗口覆盖、是否真的没有重大变化必须由域层验证。`10_final_review/tests`是本包的离线反例演示，不是完整生产授权系统。

所有新增schema $id是标识不是网络地址，验证使用本地注册，不联网自动获取；测试脚本不安装依赖。JSON重复键、无穷数和不可解析Unicode在导入边界拒绝，不通过重序列化洗掉异常。


## 7. 收集对象到Article的准确映射

resource_id→article_id；version_id→article_version_id；version_observed_at和version_observation_key原样传递；source_published_at→published_at；published_precision统一date（旧day只在适配器转换）；extraction_digest→content_digest；source_content_digest表示另一个原始内容摘要；extractor_version→extraction_method中的显式版本标识。来源状态与当前可访问性保持独立。原始正文未获准保留时source_content_digest可空，不能为了非空约束下载受限内容。

Reference DDL已同步新增观察字段与唯一键，仅通过内存SQLite语法检查；对现有生产schema的迁移、索引和并发需开发者核验。

# 第一性原理验收：系统究竟替用户减少了什么错误

## 1. 六个反问

1. 删除这一指标、角色或服务，用户的答案、证据或操作成本是否真的变差？若不变，它不是默认必需件。
2. 换一份同样流畅但不相关的材料，报告是否仍几乎相同？若相同，分析可能只是模板修辞。
3. 把价格方向反过来而维持新闻不变，解释是否随意换成相反故事？需要预声明比较和反证，不能靠事后叙事。
4. 把关键来源停掉，系统会显示不知道，还是继续报“市场平静”？覆盖要在结论之前检查。
5. 把一篇曾被引用的文章更正或撤回，历史研究能否诚实呈现当时看到什么和后来变化，而非只保留正确幸存版本？
6. 将模型去掉保留同样材料，是否已经能回答问题？若可以，不为使用模型而强制调用。

这些是设计与实验问题，不是本轮已经测得的系统缺陷或收益。

## 2. 评价矩阵

|组|材料|生成|目的|
|---|---|---|---|
|V00|当前允许取得的材料|合理确定性模板|最简单可用基线|
|V01|当前材料|受约束模型|模型在相同输入上的增量|
|V10|新增独立来源/更正后的材料|同一模板|收集增量|
|V11|同V10材料|同V01模型/预算约束|组合增量与额外错误|

当前工作区旧报告作为附加参考，不刻意制作一个低质量模板衬托升级。比较窗口、来源权利、任务、可读长度、输出语言与判定标准事先固定；额外搜索需单列费用并将新增证据也交给模板组。

## 3. 有限参考全集与盲点

先声明来源面板和研究问题，用独立人工抽样或另一组获准来源核查遗漏。参考面板不能只来自新系统已经收集和选中的内容，否则未采集事件天然不进入错误分母。被抑制队列保留样本，重要更正必须能被识别；面板之外未知，不声称全网召回。

单人项目可采用分批盲化复核、调整等价任务顺序，但不冒充独立专家共识。关键错误计数、每类分母和无法评价数同时报告；不要用几条合成反例推生产准确率。

## 4. 区分四种正确性

结构正确：字段及类型可用。语义正确：单位、时间、来源、版本和状态一致。论证支持：证据确实支持相应主张，解释没有超出观察。任务价值：使用者更少误读或重复劳动。前一层通过不能代替后一层。

描述规则可以有人工阈值，只需明确其意义并验证价值。预测概率才需要明确目标、发布时间、结算来源和前瞻评价；数据质量、阅读优先级、历史分位均不能偷换成上涨概率。

## 5. 停止与放大条件

新源只有转载增量：不扩大采集。模型主要增加空泛解释：退回模板。来源质量差：修数据或限定适用范围，不先升级模型。稀疏样本不稳定：展示未知与原始分布，不继续调到好结果。性能已满足任务：不引入新数据库。用户更愿意看长报告本身可记录，但不是金融准确率证据。

值得放大的证据是：能定位此前遗漏的有效事件/更正；能减少具体错误；能改变一次明确的研究答案或下一核查步骤；在成本与维护负担内可重复做到。没有测量前不填写提升百分比。

## 6. 首交前必须通过的定性门

缺失不填中性；不自称没有启用的数据提供确认；来源不足与无变化不同；同输入语义可复算；旧报告不被新数据无痕替换；受限内容不因历史审计而外发；用户能从简报打开所用证据；任务结束或取消不残留无界重试。除这些边界外，不要求所有未来能力先完工。
