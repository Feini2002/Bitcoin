# RES24｜信息价值覆盖与降噪评价

研究日期：2026-09-16。本卷是独立基础研究，不要求匹配当前仓库；“建议/迁移启示”是本研究的推论，不是项目官方承诺。未运行候选代码。


## 1. 少说不等于少噪音

把报告从二十条压成三条，可能减少重复，也可能删掉唯一重要反证。降噪必须同时量测无关减少、重复减少、关键变化召回与证据支持。资料更少只有在用户更容易完成研究任务时才算改善。

Media Cloud的来源集合思路和Feedly的聚类/去重区分有助于定义覆盖与阅读单位；它们不是金融重要性评分器。[EXT030｜Media Cloud API v4客户端说明](https://raw.githubusercontent.com/mediacloud/api-client/main/README.md) [EXT102｜Feedly 主题事件聚类](https://docs.feedly.com/article/552-what-is-clustering) [EXT101｜Feedly 内容去重规则](https://docs.feedly.com/article/218-how-does-deduplication-work)

## 2. 四种分母

采集覆盖按预定义主题/来源/事件集合；正文抽取按应保留的关键主张；事件归并按人工标注事件簇；报告评价按需要证据的主张。每个分母都要说明范围，不能把“全网重要事件”当一个已知全集。

扩来源会改变文章数量与情绪分布。新闻量上升可能只是新增了一个转载源；应保留固定来源面板对照，新增来源单独评估独立事件增量和延迟。不能将访问失败导致文章减少解释为情绪降温。

## 3. 重要变化与未知

建议规则优先识别已跟踪条件改变、来源更正/撤回、关键数据超期、不同独立来源冲突以及预定催化剂临近。新颖不等于重要，官方例行重复说明可能不值得提醒；旧事件的官方否认则可能很重要。

无重大变化需要满足关键来源健康和覆盖可用。如果源停采或模型未读取正文，应返回信息不足/局部覆盖，不输出平静结论。质量下降本身可以成为站内提示，但不能伪装市场风险分。

## 4. 用户效率实验

固定三类任务：查清一个数字、识别一条关键反证、恢复一份过去判断。旧版与新版使用同一材料，记录完成时间、错误、跳转和是否能解释局限。再做自然使用观察，确认实验提升没有被实际噪音抵消。

不要仅测阅读时长：更短可能是放弃阅读。记录用户是否完成目标与主观认知负担，但不把主观满意代替数值正确。重要事件遗漏必须有独立人工审查样本，而不是模型自评。

## 5. 经济价值与停止规则

每增加一个来源或Agent，比较新增独立证据、修正错误次数和维护工时。只增加重复摘要、不增加可核验信息时应退役。付费数据能节省持续清洗人力时也可能有价值，费用不是唯一指标。

预设停止条件：关键误合并超过允许边界、预算反复失控、无法确认数据用途、真实样本无增量、来源长时间不可用且没有替代。阈值由项目在测试前定，不以本报告编造精确比例。资料库记录这些反例，是为了帮助下一次选择，而不是积累越来越多必做项。
