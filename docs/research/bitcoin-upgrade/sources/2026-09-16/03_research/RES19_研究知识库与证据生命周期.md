# RES19｜研究知识库与证据生命周期

研究日期：2026-09-16。本卷是独立基础研究，不要求匹配当前仓库；“建议/迁移启示”是本研究的推论，不是项目官方承诺。未运行候选代码。


## 1. 三种知识不要混在一个索引

方法库保存论文、协议、工具卡；事件库保存现实变化和主张版本；观点库保存使用者当时判断。它们可以关联，但更新节奏、事实意义和权利不同。工具教程不能支持当前行情，旧观点也不能被检索成今天已确认事实。

Zotero适合文献与引用管理，ninjs适合新闻对象，Web Annotation适合定位。资料库可只吸收必要结构，而不要求同时安装三个完整系统。[EXT044｜Zotero Web API v3](https://www.zotero.org/support/dev/web_api/v3/) [EXT041｜IPTC ninjs 用户指南](https://www.iptc.org/std/ninjs/userguide/) [EXT043｜W3C Web Annotation Data Model](https://www.w3.org/TR/annotation-model/)

## 2. 推荐生命周期

来源发现只是候选；已读材料需要记录取得范围；结构化抽取还是待审主张；只有指定证据支持的有限陈述才能升级为可引用。发表方更正、内容撤回、许可变化和方法升级均产生版本事件。

状态至少区分read_partial、read_full、metadata_only、access_denied、stale、superseded、retracted与rights_restricted。已读不等于已验证，已验证一项字段不等于整篇文档已核全。

## 3. 引用定位与可移植性

每条结论有source_id、文档版本、实际读取时间、相关段落/选择器和支持范围。对源码还需要版本/commit及路径；本轮大量资料是浮动官方页面，采用前锁定，不能把当前页面当永久历史证据。

不要存储整个网页镜像来制造“权威资料库”。本包保存原创摘要、方法分析和链接；第三方全文、PDF、图片和代码仅在明确允许时另取得，且遵守具体用途。用户原报告作为自有输入可以保留，但不能宣称本轮重查其每个外部来源。

## 4. 更正与撤销传播

维护关系图：源版本→抽取主张→事件版本→证据包→报告→索引/缓存。源被更正时，给受影响报告附加说明，不一定自动重算全部；源权利撤销时限制对应用途并清理应删除副本。向量、摘要、缓存和导出不能成为绕过删除的隐藏副本。

内容哈希可以发现变化，却无法证明变化是事实更正；相同哈希也不证明来源独立或内容真实。研究者仍需判断变更性质。缓存清理和报告复现之间冲突时，权利约束优先，并诚实降低恢复等级。

## 5. 资料库如何持续有用

每个工具卡有重新核验触发：许可证改变、关键API弃用、维护者停止支持、目标场景改变或实测不再符合。固定日期的报告可以继续作为历史研究，但不能当作永远最新的安装指南。

定期回顾不等于定期重写全部文档。先复查对当前采用决策最关键的来源；保留未采用项及放弃原因，以免新开发代理每次从零搜索或重复尝试已经失败的路线。
