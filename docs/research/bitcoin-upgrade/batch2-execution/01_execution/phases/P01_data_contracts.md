## 4. 本阶段执行链

1. 先绑定Binance USDⓈ-M BTCUSDT主图真正消费的字段，再提供其他页面可复用的产品、价格/数量类型、单位、时间、finality和quality对象。保留原生字段和旧读接口。

2. 按任务依赖计算新鲜度和覆盖：注册、曾获取、持续采集、页面消费是不同状态；当前源健康不得冒充历史known_at健康。

3. 窗口选择返回请求窗口、实际窗口、锚点偏差和不足原因；禁止用仅一小时样本产生名为24h的变化。没有公开历史版本时不伪装当时可见。

4. 抽取本次需要的纯函数，now、cutoff、参数显式传入；无法安全共享时保留适配和差异测试，不以抽象为由搬全目录。

5. 主线必须拒绝同一身份下语义冲突或同键不同内容的无声覆盖；NEW-026仅控制有实测依据的存储优化，不能成为延后正确性检查的理由。

## 5. 阶段验收与跨页关系

1. 错产品、负量、非法OHLC、taker大于total等相关反例可定位拒绝；合法0与缺失不同。

2. 当前周期过期不会被另一新鲜周期掩盖；模型和页面取得同一语义。

3. 只对本次方法注册，不强行建设企业级元数据平台；所有新对象都映射实际消费者。

相关原场景：CHECK-001、CHECK-002、CHECK-003、CHECK-007、CHECK-021、CHECK-028、CHECK-029、CHECK-033、CHECK-034、CHECK-035、CHECK-036、CHECK-041、CHECK-042、CHECK-043、CHECK-044、CHECK-047、CHECK-050、CHECK-052、CHECK-059、CHECK-065。P00是测试路由/基线，P10是全范围汇总；两者列全场景不表示开工前须完成全系统测试。

## 6. 阻塞与回退

上游字段不足时，返回缺失和限制；可继续开发并测试适配，不给历史补造venue、quoteVolume或finality。

不得把“安全降级可用”写成原功能已实现；不得把缺生产权限写成代码不可继续开发。代码路径确实依赖当前缺失材料时暂停该依赖链，记录可继续的独立任务。
