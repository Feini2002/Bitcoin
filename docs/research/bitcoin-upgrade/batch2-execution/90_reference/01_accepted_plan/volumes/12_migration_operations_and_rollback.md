# 卷 12｜迁移、兼容、运行手册、安全与退出机制

## 1. 本卷不是部署指令

仓库调查针对含大量未提交/未跟踪变更的当前工作区，本地配置与远程实际状态不同；旧HEAD不能代表完整工作区，远程Cron、路由、数据库版本未知。实施前需只读记录真实边界，不可直接checkout旧提交、git reset、覆盖并发治理文件或执行远程迁移。[R01｜仓库事实报告§导言，L3-10](../inputs/repository_facts.md) [R03｜仓库事实报告§1.3，L28-36](../inputs/repository_facts.md)

本方案允许架构调整，但所有迁移以能力和数据owner为单位。部署、计费数据、模型调用、远程写入、改变保留期和外发通知属于后续实施权限范围；文档里有任务依赖不表示把人工审批做进产品每次运行流程。

任何默认配置中的数字都是待验证方案值，除非明确标为官方限额。实际预算、用户共享范围、历史保留目标和运行地点仍未知；相应设置为空时应提供确定性/只读功能，不能替用户自动购买或联网运行付费链。[R17｜仓库事实报告§11，L312-324](../inputs/repository_facts.md)

## 2. 先固定可复现工作区，不冻结开发活动

WP-001记录仓库根、工作分支、HEAD、tracked diff摘要、untracked清单、构建输出与已知测试命令；只读记录而非要求清空所有修改。排除密钥、账号、生产数据和个人文件。选择待修改文件的基线哈希，补丁提交前重新核对，发生并发变化时三方比较，不粗暴覆盖。

事实报告里给出的行号只是读取时位置，实施者按职责/符号和真实文件定位，不把旧行号当稳定接口。未知函数名不能凭本方案创造后再声称原先存在。拟新增shared/research等目录要与governance布局一致，必要时用现有shared目录落地并更新绑定表。

既有治理负责导航状态、请求取消、CLI退役、发布白名单和目录规范；能力升级负责数据语义、方法、研究对象、提示词、交互与验收。双方共享触点必须指定一个修改owner，避免两套features、两套取消控制和两套模型适配。[R16｜仓库事实报告§10，L285-310](../inputs/repository_facts.md)

## 4. 四个可独立交付切片

### R0：先停止制造虚假精度

范围：FNG缺失不再回退中性50；固定分数/置信度改为明确的legacy规则状态或退出；静态文案不再宣称未启用的ETF/期权确认；AI/GitHub从BTC默认日报和模型上下文退出为独立可选频道。无需迁移数据库、购买数据或引入框架。

验收：缺失、真实50、过期50分别有正确输出；62/58/46不再被展示为可校准概率；现有已接入页面仍可用；旧报告保持历史原文与legacy说明。回退界面实现时也不能重新恢复误导性的“准确率72%”文案。

### R1：第一份真正可追证的变化简报

范围：统一有限市场输入、封存bundle、核心方法向量、变化/反证、简单模板及受约束单模型综合、预算/权限、最终报告与证据入口。仅使用现有可取得数据；期权、ETF和全部新闻不作为前置条件。

验收：固定run的窗口/数值一致，关键数字可定位；数据不足时按能力降级；用户可从一张变化卡打开依据；最终报告与预览分离；相同幂等请求不重复启动本系统同一计费步骤；供应商超时后结果或费用未知时保留outcome_unknown并先对账，不承诺外部服务严格只计费一次。模型未获授权或预算未配时，模板可独立交付。

### R2：低噪音事件、日历和研究现场

范围：事件归并、根来源独立性、反证版本、官方催化剂、绝对窗口与笔记/观点；有权利和必要数据时增加ALFRED/ETF等专题。原始新闻多不等于默认更多卡片。

验收：转载不重复提醒，更正能成为重要更新；未确认未来时间不进入正式日历；旧reportId和绝对窗口可恢复到诚实等级；多个页面共享同一研究身份，不因为拖拽图表重复调用模型。

### R3：复盘、条件预警和按证据扩展

范围：观点结果跟踪、预警状态机、有限事件研究与前瞻评估；仅在任务需求成立时启用期权截面、预测概率或批分析服务。交易执行、账户余额和仓位系统继续不在本次主线。

验收：规则满足与用户有用分开测；预测定义和结算规则事前固定；误报/遗漏/成本与简单基线比较。新能力没有增量就退出，不因为已做一半而无限追加。

## 5. 数据迁移清单

### 5.1 K线来源与物理序列

导出允许范围的旧行及主键分布，检查旧表是否有可关联同步记录。能用明确证据定位来源的行才标venue；无法证明的保留legacy_unknown，并记录migration_evidence。不得因代码默认Binance或当前latest状态是Binance而推断历史每根来源。

新写入先带source/spec/适配版本。业务BTC主图可继续回退，但回退产生新的selection segment而非同一单所历史。新计算默认不跨未知/混合来源边界；用户明确选择组合序列时使用另一method_id并说明局限。

迁移验收不是“所有字段非空”，而是旧价格不被改动、源标记诚实、可确认比例与未知范围有报告、真实回退能在API/UI/导出/模型中一致显示。source列填满假Binance属于失败。

### 5.2 足迹桶和强平历史

既有足迹基于aggTrade，不以“新增真实足迹”为名重做已有计算。迁移保存bucket参数、5m窗口、source、聚合粒度和质量；没有逐笔原文的旧桶恢复等级为聚合证据，不伪造原始序列。现有买卖/聚合/恢复测试作为回归基线。[R08｜仓库事实报告§4 B1-B2，L104-118](../inputs/repository_facts.md)

旧强平notional没有priceType/quantityType时标legacy_unknown，保持原值以便读历史，但不与新版确定口径混加为同一精确总量。新采集保留Binance ap/p和z/l/q的原字段与选择理由，Bybit p定义为破产价估值；不能把正确方向测试通过扩展为金额语义已完全验证。

计算新指标时按notional_method、source和口径版本分层。对累积数量只有稳定来源ID与正确状态时才差分，无法唯一识别的流声明有限去重，不使用所有字段哈希“保证无损去重”。

### 5.3 衍生品、宏观与稳定币

旧funding_binance/oi_binance指标键可含Bybit回退值，迁移保留source元数据并改用语义键与source分列，旧API做兼容映射。真正混合数据的历史不能仅重命名就变成单源。没有FRED/ALFRED/ETF链路的旧记录不要迁成虚构版本库。[R07｜仓库事实报告§3 A4-A5，L92-102](../inputs/repository_facts.md) [R10｜仓库事实报告§5，L133-148](../inputs/repository_facts.md)

稳定币保留供应/市值/价格口径和来源切换；旧CoinGecko历史与DeFiLlama当前点对齐时不能把市值除以默认1美元自动当供应量。已有“低权重背景”不意味着今后必须保持固定权重，新系统优先显示独立语境而非加入市场总分。

### 5.4 快照与报告

旧snapshotVersion/sourceFingerprint保留作为legacy标识，新内容摘要不覆盖它。用当前还存在的输入构建新hash时，标明“迁移时可见输入”，不能声称当年就保存了这些字节。旧fingerprint只看时间/行数的盲区不能靠换字段名修复。[R06｜仓库事实报告§3 A1-A3，L62-90](../inputs/repository_facts.md)

旧reportId写入legacy_link，保存当时report_json、正文、market_snapshot_json、source_refs/grounding的可保留范围。若旧报告混有受额外条款限制的内容，先做权利分类，不整批扩大保留或重新送给模型。7天清理过的内容不能由30天API参数恢复；已缺失记录用missing说明。[R11｜仓库事实报告§6，L150-181](../inputs/repository_facts.md)

## 6. 双写、影子读与切换

优先采用“旧主写不动，新研究捕获读取其结果”的影子方式，避免在最早阶段同时维护两套行情写入。必须新增source字段时由同一采集owner写入，不建立第二个重复WS采集器。

确有双写需求时定义主记录、补偿队列和成功语义：旧写成功新写失败不能向用户宣称v2完整；记录待补偿，幂等重放。不同数据库/对象存储没有天然原子性，不能把两次await看作事务。切换读之前验证同步缺口和来源语义。

影子报告默认先运行确定性模板，只有预算明确时才对少量样本调用模型；不能为了A/B全天生成两套昂贵报告却不计入预算。影子输出与正式输出有独立标签，不混入用户历史作为真实已发布观点。

feature flags在run创建时封存，不能任务跑到一半因全局设置改变而切换model/方法/来源。关键安全policy撤销例外，应立即阻止后续外发/显示，但记录中止原因而不是悄悄改run配置。

## 7. 回退设计

回退按读取、写入、任务、UI四层分开。UI问题可以切回旧页面并保留新数据；新方法问题可恢复旧可信方法但显示legacy边界；新源问题只停该source；模型问题改模板，不必撤回已经正确的数据层。

不通过drop表、删除新artifact或git reset实现业务回退。保持新版本可读，停止有问题的producer，恢复最后可信的reader配置；必要时在报告页发布更正关系。已经对外发送的错误报告不能靠覆盖旧ID消失，需保留允许的更正轨迹。

回退不能重新引入已确认误导语义。固定概率、缺失填50、混源历史标单源、未经许可外发等属于无论使用新旧界面都要阻止的底线。可回退的是实现方式，不是已经澄清的事实边界。

## 9. 保留期、引用图与删除

保留期是产品需要、成本和来源权利的交集。报告、输入证据、原始高频数据、模型step、预览、预算账本和日志分别配置；不能简单全部改为一年，也不能保留报告却自动删掉所有必要证据仍宣称可重放。

清理任务先生成dry-run影响清单：将删除哪些artifact、哪些pinned views降级、哪些report失去exact_inputs、哪些source policy要求删除。配置尚未明确时不得启动新的破坏性清理；但遇到明确到期/撤销义务，不能因“用户未设置保留期”而继续无限保存受限材料，应阻止使用并按相应政策处理。

研究笔记中用户自己写的假设可与来源原文分离。删除来源正文后可保留允许的标识/用户评论，但需降低证据支持度和恢复等级。导出的本地副本未必能远程召回，产品不能承诺能抹去所有曾经下载的内容。

现有snapshot30天且最多500条、reports默认7天的组合对长期复盘不足，但实际目标保留长度未知。应在设置中明确“当前可回看范围”，新增长期观点库先保存必要、获准证据，不等待完整逐笔归档才提供价值。[R06｜仓库事实报告§3 A1-A3，L62-90](../inputs/repository_facts.md)

## 10. 权利策略的运行落点

每个来源明确store_raw/store_derived/display_private/display_public/send_to_model/export和到期，unknown不自动升级allowed。策略记录来自已确认条款与实际合同，不由模型投票或新闻摘要产生。

普通Gemini生成与Google Search Grounding具有不同使用约束。已有grounding_json和事实池不能据此被认定违法，也不能据此认定长期索引/二次分析都获准；实施者核对实际API、付费状态、用途及适用合同。设计采用两条路径：获准来源→可归档研究证据；Grounding→符合适用规则的独立用户回答，不默认进入长期事实库。[S024｜Gemini API附加条款](https://ai.google.dev/gemini-api/terms)

这不是用另一爬虫“洗掉”Grounding限制。不得先由Grounding收集链接再自动爬取建索引；长期来源发现使用独立注册源、官方日历/RSS或明确获准服务。Grounding允许的特定历史展示/临时改进等例外不等于普遍可用于分析数据库，具体实现仍需核验。

模型输入若含保密笔记、账户数据或商业材料，必须与所用付费/免费服务条款匹配；本方案不默认将用户私人笔记送入搜索Grounding。数据权限必须在工具和导出入口再检查，prompt中的“不要外泄”不是安全控制。

## 11. 安全设计

### 11.1 认证与共享

即使当前只给个人使用，研究API的创建、报告、笔记、预算、导出和管理都需认证。已有认证是否存在未知；缺少时，这是启用公网写API的必要工作，不是创建一套完整企业IAM的借口。私有对象按owner校验，cookie认证配合CSRF/Origin策略；token不得出现在URL、静态包或报告正文。

CORS显式允许已知前端源，不以`*`配凭据。前端Pages资产白名单继续负责排除server配置、facts原文和研究私有文件；新增文档包也不应自动进入网站发布目录。[R16｜仓库事实报告§10，L285-310](../inputs/repository_facts.md)

### 11.2 工具与外部URL

默认工具接受source_id或注册instrument，不接受任意URL。确有获取链接需要时做协议、域、路径、重定向、目标IP和响应大小检查，阻断本地/内网/元数据地址、file协议和重绑定绕过；模型不能请求任意SQL、命令或存储key。

单个来源响应有超时、大小和解析深度上限，异常返回source_error而非挂死所有任务。网络错误与解析错误分开，保存允许的短诊断；重试有次数/总预算边界，遵守限流与Retry-After，不设计绕过地区或认证限制的方式。

### 11.3 外部内容与渲染

文章、仓库README和模型输出均为不可信内容。Markdown渲染限制危险HTML、脚本、事件属性和不安全链接；提示注入文本不得改变system、工具权限或预算。安全审查不是删掉所有反对观点，而是阻断把材料中的命令当成执行指令。

Grounding相关展示还应遵守其专门显示要求，不能随意混排/修改其结果再称合规；具体安全容器与官方展示规则需独立验证。不将完整供应商原始响应输出到浏览器控制台或错误页。

## 12. 故障运行手册

| 症状 | 先看什么 | 应采取的有界动作 |
|---|---|---|
| 主图有价格但报告旧 | capture/run/model/validation/publish各阶段时间 | 标stale；不凭主图WS正常认定报告数据新鲜 |
| 一个来源断线 | 来源序列、重连、最后完整窗口 | 隔离来源，显示回退段；必要方法降级 |
| 大量重复事件 | canonical URL、origin group、event merge版本 | 停自动合并/展示重复，保留输入供回归 |
| 模型超时但可能已收费 | provider request ID与budget reservation | 标outcome_unknown，先对账，避免无上限重试 |
| report显示数值不一致 | bundle、method、cache key、client state revision | 让权威证据定位差异，不让模型解释数字冲突 |
| 清理后旧view失效 | manifest、policy、artifact availability、清理日志 | 恢复允许备份或降级restore level，不换latest冒充 |
| 多任务抢占写状态 | lease_epoch、revision、idempotency键 | 只允许当前owner提交，迟到结果隔离 |
| 成本异常 | 所有入口的root budget与search/query用量 | 关闭计费分支保留模板；核是否有绕过账本的旧路径 |

所有修复需留下最小根因和复现样本。不要通过提高超时、扩大重试、关闭校验或增加更多Agent掩盖问题。紧急关闭模型调用不能同时切断已可用的确定性市场事实。

## 13. 恢复演练

选择一个允许的历史run，复制必要artifact/manifest到隔离环境，清空可重建cache后恢复报告、绝对窗口和metric引用。分别模拟缺原始逐笔、缺文章正文、policy限制和对象损坏，验证restore_level变化真实。

备份恢复不仅检查数据库能启动，还要确认引用图、对象digest、owner和方法版本。供应商模型可能不确定且版本会变化，能重演请求和确定性事实不等于生成逐字相同报告；原报告artifact可读与新模型重写必须区分。

故障演练使用合成/授权副本，不删除生产缓存或数据来“做测试”。是否启用真实远程恢复由后续实施授权明确，本轮没有执行。

## 14. 变更责任与交接

每个WP指定一个领域owner：市场适配、研究捕获、方法、内容、模型、界面、运维/验收。不是要求七个人，而是让单人也知道同一职责在哪个模块维护。共享schema与method注册表变更需通知所有消费者，避免前端、导出、报告各自解释。

交付阶段提交实际改动清单、schema版本、迁移dry-run、测试结果、剩余未知和回退方法；不得只报告“页面可打开”。治理修改和业务修改能独立审阅时分提交，不能依赖重新组织整个仓库才能解释一项指标变更。

最终退出标准是用户任务和能力合同成立，而不是planned导航全部变成绿色。期权、ETF、全节点、GPU、多代理或数据库迁移即使未启用，也不影响已完成切片交付；同时文档明确列出其条件，不能伪称所有业务已实现。
