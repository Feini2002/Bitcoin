# TOOL013｜Media Cloud

查询日期：2026-09-16。已核验事实仅限下列直接材料；实验未执行。

## 身份与直接证据

类型：新闻来源集合与研究API。

已核验：当前API v4客户端说明包括跨平台搜索，以及collection/source/feed目录。它提供“研究哪些媒体、哪些来源集合”的参考，不只是关键词搜索。

[EXT030｜Media Cloud API v4客户端说明](https://raw.githubusercontent.com/mediacloud/api-client/main/README.md)

## 可以吸收的具体成果

复用来源集合管理和媒体覆盖审计思路；若服务授权允许，可通过API发现现有订阅漏掉的来源，或构建固定媒体面板，比较事件分布随覆盖变化的敏感性。

## 不适用与负面证据

来源数量变化会改变新闻量；抓到更多报道不一定意味着关注度增长。旧mediacloud客户端与当前v4不能混用。客户端开源不表示全部内容和历史无条件免费。

## 代码、数据与服务权利

当前README标识MIT；独立许可文件与具体API合同/配额本轮未核全，直接商业复用前补核。新闻全文和研究数据子集的权利分别处理。

## 运行与成本边界

Python客户端与API key。服务、语料与查询限额需要确认；本研究没有创建账号、下载文章或验证覆盖。

## 维护证据及其限度

当前说明含新API与测试目录，证明存在维护入口；不证明每个来源持续可采或所有历史一致。

## 竞争替代与选型条件

GDELT用于广域发现、Event Registry用于商业事件查询，Media Cloud更值得作为固定来源集合的研究对照。

## 最低成本核验实验

固定一组事件及媒体集合，检查来源可解释性、时间筛选、分页和缺失。评价新增唯一原始事件，而不是命中条数。无法得到稳定面板时，不做新闻量时间序列。

## 两轴判断

**一般适用性：**适合新闻覆盖与来源偏差研究，是前方案不足的领域。

**当前仓库适用性：**先用它审计收集盲区；不要求成为BTC在线每次报告的必调服务。
