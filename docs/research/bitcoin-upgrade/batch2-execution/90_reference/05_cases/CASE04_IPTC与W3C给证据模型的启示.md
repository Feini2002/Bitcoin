# CASE04｜IPTC与W3C给证据模型的启示

资料核验：2026-09-16。这里分析已公开的产品/方法，不声称实际使用过产品，也不复制其商业实现。


## 来源事实
ninjs提供新闻JSON规范；Web Annotation表达注释主体、目标和定位。规范有版本与不同实现范围，本案例不声称它们提供完整金融情报产品。

## 迁移设计
把ArticleVersion、Claim、EvidenceLocator分开。一篇文章新版产生新版本，主张仍可以支持或反驳同一个事件；引用绑定特定版本的段落/短片段，而不是只有主页URL。事件ID是研究聚类身份，不使用网页URL作为唯一事件键。

## 价值
这样可以回答“这段解释引用了什么”“更正影响了哪些观点”“当前网页变了为何旧报告仍这样说”。它不仅是治理字段，还直接减少核数字和重建上下文的劳动。

## 失败模式
字符偏移随着HTML清洗变化而失效；只有摘要时无法还原原句；同一短引文在正文出现多次。必须提供定位失败状态和允许的上下文，不让模型自行猜原位置。

## 实验
对相同文档插入广告、修改数字、增加否定和发布新版本。合法旧引用应仍指向旧版本，新的更正关系可见；没有保存权时降低恢复等级。完全实现两个规范不是验收条件，最小投影保持语义即可。
