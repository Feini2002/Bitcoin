# CASE03｜zenfeed与TrendRadar的情报产品取舍

资料核验：2026-09-16。这里分析已公开的产品/方法，不声称实际使用过产品，也不复制其商业实现。


## 来源事实
zenfeed官方配置围绕标签化处理和查询组织内容；TrendRadar提供聚合、筛选与推送形态。作者/社区帖子只用于发现使用问题，不把旧免费模型和效果说法当当前保证。

## 可借鉴之处
内容规则和用户偏好可配置，有助于把全量收集与实际推送分开。来源管理、通知频率、摘要批次和主题标签可以形成可复用后台，而不是每次生成日报时重新查全网。

## 金融研究需要增加的边界
标签必须说明由关键词、模型还是人工产生，并绑定版本；热点位置不能充当BTC相关性。模型的高importance分不能等同真实市场影响，原文与重写内容不能混同。更正、否认和来源失效优先保留，即使热度很低。

## 完整替换还是局部吸收
从零建设阅读系统可比较完整平台；已有事实池时可先把它们作为外部收集器输出结构化条目。只有原系统持续维护成本高、映射可行且权利满足时才考虑替换，不因为界面开箱完整就加入第二事实池。

## 样本任务
同一周获准材料比较旧流程与候选：独立重要事件、重复、误删更正、每条加工成本和人工维护。无增量就仅保留来源配置/推送节奏设计。
