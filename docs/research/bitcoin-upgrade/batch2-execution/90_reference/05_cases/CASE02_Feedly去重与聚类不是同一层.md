# CASE02｜Feedly去重与聚类不是同一层

资料核验：2026-09-16。这里分析已公开的产品/方法，不声称实际使用过产品，也不复制其商业实现。


## 已公开的做法
Feedly官方说明把内容近重复与同主题/事件分组分开，后者保留不同报道；代表文章的选择与展示位置有关。文档描述的是产品规则，不能推定其内部算法全貌或当前所有套餐可用。

## 可吸收的机制
默认显示一条代表内容，同时允许展开其余报道。对研究系统，代表应优先满足直接证据、完整上下文和适用权利，不能把更新最晚或来源最流行等同最权威。

## 反例
一家媒体把“批准”更正为“尚未批准”，正文大部分相同。若内容去重直接删掉新稿，系统恰好会丢失最重要信息。另一篇观点反驳原稿，可以属于同事件但不能算相同主张。

## 小实验与验收
采用转载、译稿、新进展、否认、更正各类配对。分别测重复阅读减少与关键反证召回，错误合并独立统计。用户应能展开来源、更改归并并看到历史关系；不允许物理删除原始记录后再宣称可回溯。

## 采用边界
借鉴交互与对象分层，不复制产品代码或固化其阈值。本仓库可以先做局部事件簇视图；商业服务是否值得买另以API、导出、权利与费用决定。
