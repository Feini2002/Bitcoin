# 运行与资料更新策略

## 资料库更新不等于线上采集

研究资料库中EXT是“这份资料曾被查阅”的证据身份；SourceCandidate是“值得考虑的运行来源”；只有实际确认用途、端点、负责人和预算后的SourceRegistration才可启用。不得把本包150余个参考链接自动批量抓取到线上。

## 复查触发

采用前重查拟锁版本、许可、关键接口与当前合同；之后由影响触发：接口响应schema变化、正文结构改变、来源长期失败、许可证变更、关键论文被修订/反驳、供应商方法调整、数据用途改变。没有必要每次升级重新搜索所有候选。

## 周期性审查建议

频率按来源发布与风险决定，不设全局每小时。官方日历临近事件可更频繁核对；方法论文通常事件驱动更新；市场流有健康监控；商业合同在用途或服务变化时复核。运行参数没有用户批准和实测预算时保留未配置。

## 故障处理

先隔离受影响来源/用途，保留失败与最后成功；不扩到关闭全部站点。已封存报告不无痕改写，新数据只生成版本或附注。恢复时重建受影响分区和索引，避免从零重爬全部历史。删除根据来源政策传播到缓存和导出，不把追溯需求当无限保存许可。

## 知识资产退役

项目停止维护、依赖风险或实测无价值时，将卡片标暂缓/设计参考，保留放弃原因与替代。旧文档留存为历史，但首页明确当前选择。不要删除失败实验，让下一次开发代理重复走同一条路。
