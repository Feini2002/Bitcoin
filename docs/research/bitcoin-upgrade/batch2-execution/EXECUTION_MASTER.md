# 第二批资料｜唯一执行总任务

**执行版：batch2-execution-1.0-design｜整理日期：2026-09-17。**

本文件是第二批资料的唯一任务调度入口。任务量较多，因此采用“本总纲＋11份主阶段MD＋1份条件分支MD”；不再让开发者从多个S1—S6切片中重新选一个计划。原48个NEW编号完整保留，其中39项进入默认本地主线、9项按证据触发。第一批已经归档的资料保持原位，本包不重新整理它。

这次整理只改变文档与执行组织，没有再次读取当前仓库、核验生产服务或运行应用测试。金融设计、代码审查与外部资料仍以各自原日期为准。原审查固定提交为`a6ef6c8974dcdaace32acf25c3a231ecd279ef37`，不是命令开发者回到这个提交。

## 1. 当前目标与明确范围

**目标：把已有市场数据变成四个页面与分析能共同使用的可信输入；完成有限情报收集、确定性简报与受约束模型增强的代码链路，再用明确的验收区分实现、运行和价值。**

默认主线覆盖：当前工作区绑定；最小产品/单位/时间/质量适配；行情工作台；足迹/订单流；强平；衍生品；固定输入与模板报告；有限来源、文档版本与事件关系；模型适配/预算/核验代码；四页证据与历史导出；本地回归和交接。

它不是“先写研究计划再停下来”。用户明确要求“执行本总任务”后，完成P00只读核对便进入代码开发，按下表持续处理就绪任务。正常的阶段验收、保存进度和下一任务不需要逐次询问是否继续。

也不是“一次性实施所有愿景”。默认不购买数据、不新增常驻服务、不迁移数据库平台、不把50项方法和32个数据集全部铺到页面、不转正所有员工/会议室原型、不接交易执行和资金账户。与当前任务无关的仓库治理不重新开展。

## 2. 哪份材料决定什么

| 问题 | 本次依据 | 不能混同 |
|---|---|---|
| 本次做什么、先做什么、阻塞后做什么 | 本文件与被链接的阶段MD | 旧S/WP/SLICE清单不能另开一条主线 |
| 具体方法、公式、页面行为和迁移语义 | `00_current/`对应设计、`02_contracts/`及当前代码核对 | 任务顺序不能修改数学含义；JSON合法不代表业务正确 |
| 当前仓库实际怎样 | 执行时真实源码、配置、测试与获准运行证据 | 固定提交或旧本地事实报告不代表今天工作区/线上 |
| 某任务做到了哪里 | 根[EXECUTION_LOG.md](EXECUTION_LOG.md) | `tasks.json`是设计索引，不是第二份进度数据库 |
| 外部组件/方法如何选 | 第一批实际归档与本包历史备用研究 | 资料出现不等于安装、采购或启用授权 |
| 本地修改、联网、费用和生产操作是否允许 | 用户本次明确指令及适用仓库规则，按用途记录 | 文件存在、已有API Key或默认配置不自动授权新用途 |

实际源码已经达到目标时，核对并保留，不为了执行文档重写。发现设计、schema、样例之间的实质冲突时，暂停受影响改动，记录冲突与证据；能由明确来源和本地实验安全消解的局部冲突可修正并记录，涉及用户目标、成本和生产风险的不擅自决定。不能仅以“文件更新”认定某份一定正确。

本文件确立的是工作范围和调度，不能覆盖更高优先级的用户指令、来源权利或安全约束。开发者实际发现目标需要另一个架构时，提交带证据的替代设计，而不是偷偷执行旧方案或全仓重写。

## 3. 一次授权下的执行方式

### 3.1 默认可连续推进的范围

用户使用下方执行指令时，范围为本地业务代码修改、必要的本地配置/迁移文件编写、已有环境内的离线测试、隔离数据演练、文档更新及对本次实际采用资料的公开只读核验。依赖安装、新服务、真实市场/模型API、生产读写、发布、删除、commit/push不包含在默认范围；如当前用户指令另外明确允许，则记录相应权限后执行。

本轮聊天只交付文档包，不替用户触发上述开发动作。下方指令由用户交给可读取仓库的开发者后才具有该次任务范围。

```text
请读取第二批资料根目录的 EXECUTION_MASTER.md，并按照其默认主线连续执行开发。
本次授权范围：本地业务代码修改、必要的本地迁移/配置文件、已有环境中的离线与隔离测试、文档更新，以及相关公开官方资料的只读核验。
先核对当前工作区与第一批已有归档，不重排、不覆盖第一批；完成P00后继续代码实现，不停在规划或只读报告，也不逐阶段询问是否继续。
只按总纲与阶段MD安排任务，原NEW编号保留。已有目标已实现则核对复用。条件分支依规则判断，外部权限不足只阻塞相应步骤；继续所有不受影响的就绪任务。
本次不安装新依赖、不连接新账号、不调用真实市场/模型API、不操作生产D1、不部署或清理、不commit/push。即使仓库说明有默认部署，本次用户范围仍明确不部署。
不得把合成数据作为生产fallback，不得只生成空模块或仅修改文案后声称完成。每项分别记录实现、实际测试、启用及效果；阶段结束更新EXECUTION_LOG.md并继续。
若受上下文或运行限制必须中断，写清最后完成任务、下一就绪任务、文件差异和未解决项；下次从日志继续，不声称后台自动开发。
```

如果用户这次已经明确授权某项真实调用、安装或发布，不要求重复确认同一权限；将证据记录在日志并按范围使用。没有授权的部分不自动推定允许。需要新增包时先说明解决的真实问题、版本/许可/替代、安装影响；已有环境可继续的工作不停止。

### 3.2 不把测试前置变成全仓工程

每阶段先读取该阶段最少材料，接相应反例到已有测试，再做方法和消费方。NEW-003提供测试底座和基线，不要求开工前把66项全部接完；NEW-044在收口时检查全映射。构建命令可能串联其他脚本，必须先核其副作用；不直接运行未知deploy、prune、import或在线probe。

浏览器/API联调必须使用获准的本地或隔离环境，拦截/替换市场与模型请求；默认禁止真实网络。启动本地前端若仍指向生产Cloudflare，不算离线测试，不得直接打开后让它自动同步生产。使用真实网络的检查单独登记权限与结果。

一个本地测试可以使用固定合成样本来证明边界行为；不能用同一合成样本证明真实数据完整率、模型准确率或用户收益。纯文档QA与业务测试必须分别保存。

## 5. 阻塞时怎样继续，而不是停在询问

选择默认顺序中最早且实际硬依赖已满足的任务。某项阻塞时先写原因、受影响能力、可安全完成的子范围和解除条件，然后继续无依赖冲突的任务。不能因主图真实网络受限，就停止衍生品纯计算、情报规则或模型模拟测试。

| 遇到情况 | 必须采取的行为 | 不能采取的行为 |
|---|---|---|
| 当前代码已经修复旧问题 | 保存当前实现和回归证据，标`reused_verified`，继续下一项 | 回到旧提交重造问题，或只凭名字判断已实现 |
| 无真实数据/模型权限 | 完成可独立的代码、适配、拒绝分支和离线验证，live部分标blocked | 声称接口接通、生产持续或效果已验证 |
| 必需上游技术能力未实现 | 暂停依赖该能力的部分，继续独立任务 | 用null/假样本让正常路径表面通过，隐藏核心欠账 |
| 单个来源字段不足 | 限定真实能力与显示，并记录需要的来源证据 | 换源冒充或用模型补数 |
| 一项条件任务未触发 | 标deferred及重新触发证据，不计主线未完成 | 为清零待办强行迁库、接数据、装框架 |
| 共享文件有并发修改 | 保存基线、进行三方核对或暂缓该文件，其他独立模块继续 | reset/clean、整文件覆盖或清除他人未提交变更 |
| 新测试失败 | 判断是实现、样本还是契约问题；修正要有证据 | 删测试、无限重试、提高阈值只为变绿 |
| 本轮必须中断 | 更新最后结果、下一就绪任务、精确恢复位置和阻塞 | 将阶段暂停写成系统完成，或承诺自行后台继续 |

代码与本地契约通过可以供下游使用该已实现的接口进行隔离开发；但真实启用必须重新检查来源健康、用途、费用与生产条件。一个任务同时有本地和真实验收时，日志分别记状态，不以离线通过自动满足live依赖。

## 8. 共同责任与最小改动原则

来源/规格与数据归一化一个维护位置；同一方法一个权威实现或明确差异适配；一次报告一个capture责任方；预算一个根账本；页面、导出、快照只消费同一语义。责任可以由一个人兼任，不等于要建多个服务或Agent。

金融主数据、纯方法和报告身份是职责，不是要求先搭企业元数据平台。只有实际消费者需要的字段才进入本次实现。保持现有技术栈是起点，不是禁止合理替代；替代必须带证据与回退，不因资料有某工具就安装。

每项修改应回答：影响了哪个页面/快照/模型输入/缓存/导出/历史；哪些不受影响及依据。只改前端标签而后台仍传旧分数不算完成，机械修改全仓也不算更完整。

## 9. 进度、检查点与恢复

使用唯一[EXECUTION_LOG.md](EXECUTION_LOG.md)记录实际进度。它初始为空记录和待执行状态，不是本次生成器已经跑过业务。阶段正文保持设计稳定，日志保存真实代码位置、变更、测试和授权。

每个NEW任务至少记录四个轴：

| 轴 | 建议状态 | 用途 |
|---|---|---|
| 实现 | not_started / in_progress / implemented / reused_verified / partial / blocked / deferred | 是否真正完成对应代码或复用了已成立实现 |
| 验证 | not_run / offline_pass / integration_pass / live_pass / failed / blocked | 哪类测试实际运行；允许分别列离线与live |
| 启用 | not_activated / local_only / production_observed / blocked / not_applicable | 不把本地运行当线上生效 |
| 效果 | not_measured / evaluated / not_applicable | 不把接口/Schema通过当研究增量 |

完成一个任务后更新真实文件、验收命令与结果、未满足部分和回退；完成阶段后写下一就绪任务。已有实现无需改代码时也必须给行为或测试证据。只复制文件、出现按钮或服务启动不算实现完成。

同一个“implemented”不能覆盖原任务中的未测真实效果；例如模型综合实现与离线核验通过，而效果尚未测，应同时写明`implemented / offline_pass / not_activated / not_measured`，不可归并为“全部完成”。
