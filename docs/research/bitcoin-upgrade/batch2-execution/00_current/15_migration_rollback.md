# 15｜迁移、兼容、回退与并发治理边界

## 1. 当前提交与本机工作区分开

本包审查固定GitHub提交a6ef6c8，不覆盖用户本机未提交变化。此前事实报告针对有大量未提交/未跟踪文件的工作区，不能简单按旧HEAD或本包SHA执行reset。实施前只读记录当前branch/HEAD、相关diff、配置与受影响文件摘要，确定哪些旧问题已修复，哪些新的变化需要保留。

新包的任务仅针对能力升级；现有发布白名单、目录治理、CLI退役、请求取消和构建规则不重复新建。共享`finance`、行情Worker、snapshot、yuqing和导航文件由一个集成负责人合并，避免多个Codex会话覆盖整文件。

## 2. 迁移总图

```text
旧OHLCV/足迹/强平/衍生品 ──→ 保留旧只读与legacy说明
          │
新finance规范数据 ──→ 逐族质量与规格 ──→ 四页新版读取
          │                                  │
          └──→ 同一capture与方法 ──→ 模板/模型简报
获准情报 ──→ 文档/主张版本 ──────────┘
旧reportId/视口 ──→ 兼容读取 / 明确恢复等级
新研究选择 ──→ 绝对窗口、报告版本、观点和评价
```

优先影子读取新数据与旧页面对照，不同时双写所有行情表。确需双写时记录主写、投影失败与补偿，不把两次await当跨库事务。迁移价值是语义和行为变得明确，不是表名变整齐。

## 3. 数据兼容矩阵

| 旧对象 | 新处理 | 不允许做 |
|---|---|---|
| 无source旧K线 | legacy_unknown或有证据的来源映射，保持价格 | 按当前币安默认补全部历史venue |
| 只有OHLCV的旧K线 | 可重算合法近似指标，恢复范围明确 | 虚构quoteVolume、逐笔、原生x确认 |

## 4. 每个切片的发布步骤

先准备固定样本及旧行为基线；建立新增字段/兼容映射；影子计算或影子读取；对比差异并分类为预期方法变化、修复或新错误；经本次验收后切换一个消费者；观察失败与资源；再扩大到快照、报告和导出。

主图、足迹、强平、衍生品可以逐页交付，但每页的同名方法消费者必须同时获得版本或明确隔离。不能只改前端POC而让快照继续旧算法；也不能因要保持数字相同而保留已证明错误。

## 5. 切换开关

开关按能力而非整个新平台：规范K线、确认视图、精确VWAP、POC tie v2、typed liquidation、typed derivatives、bundle report、event pipeline等。每个run创建时冻结选用开关，执行中不随全局设置任意改变来源/模型。

紧急安全或权限撤销可以中止当前任务，但记录原因，不能悄悄更换证据后继续同一报告。关闭模型不应关闭已可用模板；关闭期权不影响价格简报；关闭新采集器不删除已有合法研究历史。

## 6. 回退单位

UI回退、方法回退、读取回退、生产写入停用分别处理。新UI有问题可以回旧布局但继续显示真实source和缺失；新算法需要复核可以停止该方法，不能恢复“72%已校准”或unknown→long这样的错误语义。

新数据库/表不靠DROP回退，保留只读以核对结果。错写数据要隔离并记录修复版本，不用覆盖隐藏。外发错误报告需更正关系，不能通过删除ID抹去历史。跨源错误值修复也要保留对应版本和影响清单。

## 7. 保留与清理

原始响应、规范观察、capture、报告、模型预览、usage、笔记、索引分别设置保留目标。它是研究需求、权利与成本的交集，不统一改成永久。配置为空不自动批准无限保存，也不自动启动破坏性清理。

清理先dry-run：列对象、引用报告、恢复等级下降、source权利、预计空间与是否可以恢复。用户pinned记录不能无条件超越来源删除义务。已下载外部副本不保证可远程撤回，产品要如实说明。

## 8. 文件和命令边界

当前Node要求>=24<25，现有测试、构建和部署有明确脚本。`npm run build`先验证再构建，`deploy:pages`实际部署并清理旧部署，不能把后者当普通检查命令。`diagnose`与API smoke可能联网；安装浏览器或npm依赖也不是本轮已经执行的事。[C30｜package.json（读取范围见登记）](https://github.com/Feini2002/Bitcoin/blob/a6ef6c8974dcdaace32acf25c3a231ecd279ef37/package.json#L1)

后续执行报告必须列真实运行命令、输入范围、结果和未运行原因；旧文档161/96/15个PASS标记及以前文档检查数不作为本次测试通过证据。不要拿文档自身JSON可解析冒充业务无错误。

## 9. 生产切换前核验

确认实际Worker路由、D1绑定、迁移版本、Cron、源可达性、凭据用途、公共/私有展示、预算和回滚开关；这些不由repo配置文件单独证明。固定提交审查不能认证现在生产与本机相同。

若任何核心身份或源语义未通过，缩小到已确认数据的模板切片；若数据有效而模型失败，只停模型；若持续采集不可行，选择合法维护条件满足的替代运行路线，而不是提高无限重试。每次退出留证据，减少下一个代理重走错误路径。
