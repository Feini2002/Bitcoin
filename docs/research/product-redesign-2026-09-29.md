# 研究工作台重构：产品判断与实施记录

## 目标与依据

用户于 2026-09-29 授权全站逐页审查、自主选择设计方向、重做事件与舆情模块，并明确以后由 AI 对话发起分析，不接模型 API Key。当前目标模式以实际实现、模块提示词、截图及行为验证、发布为完成条件。

风险 L3：跨页面与既有报告的兼容、线上静态发布。保留四页的数据 API、时间来源及导出契约；不重建数据库、不删除历史报告、不恢复已退役模型执行端点。远程报告写入仍复用独立导入脚本，显式选择目标，先校验再执行。

## 对抗审查

1. 首页是重复的接入声明而非研究入口。用户无法快速判断从哪开始、哪些报告已过时、数据能支持什么。
2. 事件页仍有扫描、定点任务、费用和流式残留，空报告能显示 1970。舆情历史报告的零分和旧模型配置文案易被误当成当前市场观点。
3. 舆情先给 Risk-On/Risk-Off，再寻找支持数据，顺序容易造成结论先行；温度、置信百分比缺少校准，不宜以精确仪表包装。
4. 事件、叙事、市场验证混杂；文章发布时间与催化剂发生时间、热度与可信度、相关与因果均应分离。
5. 全站层级、颜色和密度不一致；大量工程解释抢占正文。诊断应该可展开，关键缺口和过期状态仍须显眼。

- [Santiment Social Trends](https://academy.santiment.net/sanbase/social-trends/)及[Sanbase](https://app.santiment.net/explorer)：区分话题、叙事、社会讨论与价格。借鉴有筛选的研究流与上下文；本系统没有全平台社媒样本，不能复制其热度指数并宣称同等覆盖。
- 本仓库 V04 §5（成交与来源）、V07（主张抽取/证据/反证提示词）作为契约依据。旧模型执行方案只作研究资料，当前用户工作方式优先。

## 选择的设计与范围

采用个人研究桌布局：浅色阅读画布、深色导航、克制的琥珀强调色；深色主题同样可用。统一字号、表格、工具栏、状态和空页面。保持高信息密度但把首屏留给最重要的事实及动作。

- 首页：研究顺序、四页数据入口及实际读取状态、最新两类报告、下一步动作；规划原型折叠保留。
- 事件一览：摘要 → 事件筛选与事实卡 → 可核验催化剂 → 待核实/冲突 → 来源。研究流程按范围、采集、去重核实、传导解释、催化剂、质检运行。
- 舆情分析：研究结论及适用时间 → 硬数据核对 → 多空观点与反证 → 情景/触发/失效 → 下一观察 → 来源与限制。无覆盖分母时不制造热度/置信概率。
- AI 工作流：每模块有目的、输入、提示词和输出；可复制完整任务/单模块指令，导出显示证据；结构化报告本地预览校验，AI 对话使用既有 CLI 导入云端。网站不启动模型、不索取 Key。
- 兼容：新版报告有明确 schema 与来源关联校验；旧版保存原文并标历史格式，不把旧零值重新推断成当前风险判断。修复 Codex 正式研究被导入脚本误标成开发测试的问题。
- 其余页面：逐页截图，统一外壳与组件；已有图表/足迹/强平/背景的业务数据语义保持，优化拥挤工具栏与重复说明；演示/规划不擅自转成实际交易功能。

### 模块逐项判断

| 页面 / 模块 | 使用者需要回答的问题 | 实现中的约束与输出 |
| --- | --- | --- |
| 事件 / 范围 | 截至何时、研究什么？ | asOf、品种范围、覆盖限制；旧报告单独标历史 |
| 事件 / 事实 | 到底发生了什么？ | 原始披露优先；事实卡含发生时间、类别、核实状态和来源 |
| 事件 / 核实 | 是转载、传闻还是独立确认？ | 来源去重、冲突保留；按关键词及核实状态筛选 |
| 事件 / 传导 | 为何和 BTC 有关？ | 每项写影响路径与下一观察，禁止把标题直接变成交易建议 |
| 事件 / 催化剂 | 下一次何时能验证？ | 独立排期区，精确/日期/未知分开，不猜凌晨时间 |
| 事件 / 审查 | 什么会误导读者？ | 检查因果、时点、原文和缺口；保留研究边界 |
| 舆情 / 市场基线 | 真实资金与交易数据说了什么？ | 事实/解释分列、逐项时点；读取四页并校验口径 |
| 舆情 / 叙事 | 谁在说什么、样本覆盖谁？ | 定性观点与来源；不制造全市场热度或置信百分比 |
| 舆情 / 定价 | 市场是否响应了这个观点？ | supported/contested/untested，缺对照窗即未验证 |
| 舆情 / 反证 | 什么证据与当前观点冲突？ | 与支持证据并排显示最强反证，字段必填 |
| 舆情 / 情景 | 何时应该改变判断？ | 触发、确认、失效、可能影响分别列示 |
| 舆情 / 交接 | 下一次该看什么？ | 观察问题、条件、来源及上游事件报告 ID |

每个模块的完整指令位于 `js/research-protocol.js`，页面可复制单模块或完整任务。`prepare-research.cjs` 只读收集四页和两类报告，保存原始 JSON、URL、访问时间和失败项；截至 06:18 UTC 的实测为 6/6 成功返回，不据此宣称质量全部通过。导入器默认 dry-run、严格验证新版结构、同 ID 拒绝覆盖；SQLite 实测保留正文及旧行。没有将验收样本写入远程数据库。
