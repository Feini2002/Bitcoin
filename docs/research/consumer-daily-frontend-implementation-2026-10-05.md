## 3. 内容层与持续维护

### 3.1 原件和编辑稿分开

- 原件继续在 `.local/agent-team/`，原报告GET、任务导出和数值校验保持原契约。
- 独立阅读稿、译文和标题目录保存在 `.local/reader-content/`。它们与原历史一样属于本机离线资料，不纳入Git或Pages产物；换电脑需要随本机历史一起离线备份。
- 新增只读GET `reading/:reportId`：复用已有报告内容校验值，校对所选ID与阅读稿所对应的原件；取对应研究中的引用资料作图，不读取“最新价格”替代它。
- 阅读稿保留 `reportId`、已有 `sourceHash`、版本、编辑说明、标题、导语、要点、章节及原主张ID、限制与关注点。正文不增加买卖建议、概率、因果或计算结果。
- 本次内容由主助手基于已保存原件编辑，不调用模型，不触发研究。页面打开、滚动、搜索或展开时没有新增模型调用。
- 无编辑稿的旧报告明确显示“按原报告阅读”，保留全部论证。编辑稿无法核对则显示真实状态并回到原报告；未知外文材料显示“中文待整理”，原文可按需展开。
- **没有开启自动编辑/翻译任务。** 未来新报告不会自动拥有与这6份相同质量的编辑稿；这不是后台已经运行的自动日报生产链。若需要自动编辑，应另行接入官方Codex生成端，核定调用代价后启用，不能伪称本次已验证。

### 3.2 本地工具

- `node scripts/save-reading-edition.mjs <稿件JSON路径>`：明确导入一份已编辑阅读稿；校验报告身份、已有内容校验值和章节引用ID。不会改原报告或运行设置。
- `npm run reader:catalog`：扫描本机保存首席，重建小型中文标题目录，最长20秒；查询时只读取小目录，不扫描报告正文。
- `npm run verify:consumer-reading`：验证绑定、过期/缺失编辑稿、译文原条目对应、原件不变、数字/日期精度、图表断点及缺失首席目录。
- 结构校验不等于语义审核。本次已逐段核对6份稿件的方向、否定、替代解释和限制；未来编辑仍需同样审核。

手工编辑稿输入字段：`reportId`为原报告ID，`sourceHash`复用原报告已有校验值；`title`、`lead`为中文标题和导语；`highlights`、`risks`、`watch`是中文段落数组；`sections`每项含`heading`、`paragraphs`及对应原主张的`claimIds`。还可记录`editionVersion`和`editorialNote`。先核对原件再编辑，不能以格式校验代替语义审核；保存后执行`reader:catalog`刷新查询标题。工具不代写文章，也不会调用模型。
