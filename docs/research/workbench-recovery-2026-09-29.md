# 四页恢复与持续采集核验（2026-09-29）

本轮目标：恢复停机历史，确认四页真实采集推进；沿用 Cloudflare、D1、东京出口和现有单常驻对象。操作获用户恢复云端、补齐历史及本轮核验授权。本文记录实测，不承诺长期无故障。

## 依据与核验事实

- 查询日期：2026-09-29。适用代码：Wrangler 4.85.0、BTC Worker 3.11.2/3.11.3。
- [Binance USD-M aggTrades 官方说明](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)：单页最多 1000，IP 权重 20；仅最近 48 小时，时间窗不足一小时，fromId 与时间参数不同时发送。本轮保留旧游标，现有每次 14 页，人工加速每轮启动间隔至少 12 秒；不跳过可恢复历史。加速任务硬截止 40 分钟，网络错误即停止加速核对，云端 Cron 保持原频率。
- [Cloudflare D1 限制](https://developers.cloudflare.com/d1/platform/limits/)：每库串行执行，查询及结果序列化受 CPU/内存限制；索引和有界查询决定吞吐。线上旧的 15m 最新时间聚合实测读取 13481 行、SQL 14.5049 ms。修改后根据本批时间单调推进主键行，真实 D1 EXPLAIN 仅 SEARCH 主键；不把 EXPLAIN 当作写耗时测量，不断言之前 CPU 错误唯一根因已证明。
- [Workers 最佳实践](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/)、[DO WebSocket](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)和[Wrangler 命令](https://developers.cloudflare.com/workers/wrangler/commands/)用于核对发布、连接和运行边界。

## 修复

1. 强平 liveness 取事件、行情心跳及传输时间的最新值。旧逻辑优先采用第一个非零事件时间，导致安静市场下 Bybit 每分钟误重连；发布前 13 次，发布后观察窗口内保持 0。断流仍触发重连。分所桶和事件去重契约不变。
2. 3d 向前扩展直接请求交易所原生 3d，禁止把自聚合日线混进 Binance 序列。
3. 3d 原库 861 行，其中 480 行时间戳不在交易所完整原生响应中。先备份，再调用既有回补入口，逐根验证原生已收盘 OHLCV，最后删除精确备份列表的 480 行并推进历史版本；远程原始表最终 862 行。规范表检查没有非原生时间戳。没有平移、填零或合成替代数据。
4. **原生历史自身有 3 个非标准相邻间隔**：2019-09-22→09-24、09-24→09-25，以及 2023-08-14→08-16。官方返回的 closeTime 仍为起点加三日减一毫秒。不得将这些事实归咎本机断档或强行抹平。2023-08-16 之前主要格点偏移两日，之后偏移一日；连续性检测以实际棒起点加周期，避免按今天格点误报 479 处缺口。跨段异常仍保留；当前研究窗不含这些旧段。
5. 规范 K 线实时写入的 head 推进不再重复扫描全历史；迟到/失败/回补、收盘版本和历史修订规则保留。
6. 某次完整刷新已经补齐主动成交的 537 个小时点（实测无断档），旧冷却标记仍在。调度在冷却期间先核对已保存覆盖，只在 SQL 确认后推进/清除标记，不绕过尚未补齐的缺口。
7. 背景页使用已有的卡片时效阈值；不再被摘要层更短的采集目标直接覆盖。装配完成时确定 asOf，避免请求中到达的数据被误标成“未来”。没有延长原卡片阈值。
