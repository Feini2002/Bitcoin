# 数据层采用方案：保留骨架，按证据与场景推进

日期：2026-09-30。以下为审查建议，未实施、未启用、未采购。风险从实际影响判断；本轮研究与导航为 L1，后续跨模块接口为 L2，新增生产存储／来源／费用与迁移为 L3。

## A. 优先完善内容版本与冻结研究输入

**预期结果。** 相同输入版本可以表示相同事实；数字、来源、覆盖、质量或修订变化时版本变化。一次研究引用固定输入，重新打开可以确认当时确实看到了什么。

| 小步 | 影响面 | 代价与验证 |
| --- | --- | --- |
| A1 完整内容版本 | finance/desk 的 context／orderflow／heatmap；DataEngine、四页事实导出、marketSnapshotProgram 和研究准备中实际消费的位置 | 借鉴 chart 的稳定摘要／历史修订；摘要排除无意义响应时间，包含可影响结论的值、身份、窗口、来源、质量、缺口与修订。同时间纠正必须升版，排序／空轮询不应无故升版 |
| A2 证据包 | prepare-research、workbench-evidence、研究协议和未来报告输入／导入的引用关系 | 新包有完整内容 ID、截止、各范围读回和版本清单、方法版本、逐来源时间与限制；不同频率保留不同观察时间。在线报价仍可刷新，研究引用被冻结 |
| A3 历史时点验收 | dataset-store／desk 的 knownAt、发布／收据／修订规则，包与报告状态 | 保存之后到达的修订不能穿越到此前包；未知公布时间不冒充精确值；未保存的旧原始点保持未知；采集当前健康不证明历史健康 |

先检查消费实际使用，避免为“统一”改造退役链路。独立 snapshot 的 chart／derivatives 当前有意省略，不要求将其恢复；若使用它保存新证据，先定义新版本／用途契约。

**必要验收。** 现有三个反例转换为纠正后应变化；固定内容顺序变化稳定；不同数据源与单位不可碰撞；同时间修订、删除／补洞、陈旧／缺失状态改变可追溯。保存包后上游继续变化，旧包内容保持不变；无法重建时失败或明确 partial。

**现有检查。** npm run verify:finance、verify:evidence、verify:research、verify:market-snapshot 和 build。只改读口摘要未必需要 D1 迁移；持久保存方式选定后才设计加性 schema／对象目录。Worker 与 Pages 有实际改动时按现有发布顺序和缓存版本规则执行；远程 D1 不自动迁移。

## B0. 成交历史先验证官方归档回补

已有 BTC 足迹历史缺口或更长回测需求时，先验证 Binance Public Data 的合约 aggTrades 日／月文件，再决定额外采集和采购。官方文件存在性与 checksum 访问已核验，CSV 完整性和本项目聚合结果尚未核验，见[归档记录](official-history-archive.md)。

影响面为历史文件取得、校验／解析／清单、现有足迹聚合器及历史来源／覆盖标记；先离线固定一小段，核对时间单位、ID、范围、重复、缺口和聚合结果。通过后再设计有界批量导入、任务截止和加性存储。原始文件与聚合版本、获取时间、修订保留；不更改既有“历史已核实”的含义，不将下载时点倒填为当年可知，也不凭成交归档补强平或盘口。

本轮不下载大型 ZIP、不导入 D1。生产回补须先选窗口、核对远程现状、保留原数据并定义恢复边界；现有 verify:footprint、verify:finance 与 build 加上真实固定文件的离线对照，才构成适配验收。

## B. 连续盘口与原始事件归档：在需要回放时建设

**触发场景。** 需要挂撤单与流动性变化、跨所价格发现、任意价档重算、桶内顺序或长历史成交／清算研究。当前四页窗口观察可以保留聚合政策。

**范围。** 交易所适配 → 现有出口和采集器 → 快照＋增量连续性状态 → 原始批次文件与清单 → 确定性复算 → 原有规范观察／desk → 页面、证据包与研究。文件可采用对象存储和 Parquet；D1 保留热窗口、目录和采集状态。先量测事件量、字节、压缩、保留周期、写入次数及回放目标，不先建全市场管道。

**必要协议。** 原生产品／事件 ID、交易所时间、实际收据、原生序列、连接代次、schema 与 normalizer 版本；文件范围、校验和、去重和缺口。盘口按官方快照／U-u-pu 连续规则重建，缺包后退出“可用”状态再重新初始化。[Binance 官方方法](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly)

**关联文件。** kline-live-collector、LiquidationCollector／footprint 写入路径、finance/store 与 dataset-store、schema／wrangler、desk、orderflow 与 heatmap 引擎、快照、导出及研究准备；若增加归档任务则另有上传／恢复／清单脚本。

**验收。** 固定原始样本重放得到与在线聚合相同的结果；丢包／重复／乱序／重新连接可辨识；序列缺口不可被“刚有心跳”掩盖；归档失败有明确恢复边界；热窗口查询不扫描所有原始文件。运行 verify:footprint、verify:finance、verify:market-snapshot、build，补可重复回放样本。

**生产影响。** 新对象资源和保留／费用须选定精确范围，分开创建、灰度、回滚和删除政策。保持 D1 及原数据，不用清库解决；新增 raw 也补不回币安没有公布的全部强平。

## C. 按研究目标扩来源

| 研究问题 | 最小补充 | 验收与限制 |
| --- | --- | --- |
| 跨所杠杆／资金费拥挤 | 先增加 Bybit、OKX 中明确选定的一所 OI／结算费率／基差及合约规则；对照现有 Binance | 同时点与同窗口对比，原单位与美元换算均可追溯；不将采样差异或反向合约忽略。再决定第三所，避免重复公共采集 |
| 现货与合约价格发现 | 配对现货／永续实际成交与中间价，需要时再考虑 Coinbase／CME 等 | 来源时间与市场交易时钟独立，验证延迟、时区和缺口，不静默拼接为主图 |
| 期权波动／偏斜 | 产品目录、分到期／行权价／类型的报价、IV、Greeks、OI 及时间 | 摘要、标记、可成交报价分开；25-delta 插值与 GEX 假设可复算，未知方向不补值 |
| ETF／链上流 | 官方发行方／披露历史；链上实体／地址标签和修订来源 | 净申赎、持仓估值、成交额不同；实体归属和地址标签是有误差的版本化假设 |
| 新闻／社媒样本 | 原文、发布时间精度、访问时间、版本与覆盖清单 | 转载去重和冲突保留；历史无样本不写成零热度，付费／API 权限先明确 |

涉及 gateway/registry/datasets、scheduler、存储与保留、desk、前端／导出、快照和研究输入，须按真实关联一起修改。适用检查为 verify:finance、verify:derivatives、verify:yuqing、verify:evidence 与 build；来源访问和线上增量另外验收。数据源或凭据、费用、远程表变化不在本轮授权的研究实施中。

## D. 多角色架构与评价

可选研究结构：冻结证据 → 市场事实计算／事件原文核验／舆情样本检查 → 独立反证 → 条件情景 → 综合与审计。任务按证据需要分解；角色共用截止、内容 ID 和工具范围，不各自再启动采集器。数字交给确定性程序，报告保留事实／推断／假设／未知。

先用相同问题和冻结输入，对比程序模板、单助手与少量独立角色。评价来源错误、数字错误、遗漏、反证质量、结论可追溯、运行时间与费用；增加角色不作为默认质量结论。不自动恢复网站模型、安排后台任务或实际派发 Agent。
